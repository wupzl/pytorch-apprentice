一、语言模型的终极任务：预测下一个 Token

教授写下一段文本：

我 喜欢 学习 PyTorch

假设经过 Tokenizer 后得到：

[我, 喜欢, 学习, PyTorch]

每个 Token 有自己的 ID：

我       → 1
喜欢     → 2
学习     → 3
PyTorch  → 4

于是文本变成：

tokens = [1, 2, 3, 4]

林默问：

“然后呢？”

教授说：

“如果要让模型学会预测下一个 Token，我们应该怎么构造训练数据？”

他在黑板上画出：

输入：我
目标：喜欢

输入：我 喜欢
目标：学习

输入：我 喜欢 学习
目标：PyTorch

林默点头。

“相当于不断向后移动一个位置。”

“对。”

这就是：

Next Token Prediction——下一个 Token 预测。

数学上，我们希望模型学习：

P(xt∣x1,x2,…,xt−1) P(x_t\mid x_1,x_2,\ldots,x_{t-1})

意思是：

已经知道前面的 Token，预测下一个 Token 出现的概率。

教授继续：

“比如当前输入是：”

我 喜欢 学习

模型可能输出：

PyTorch   0.70
Java      0.15
Python    0.10
其他      0.05

然后根据这些概率选择下一个 Token。

这便是文本生成的起点。

四、Causal Mask：禁止偷看未来

假设有四个 Token：

A B C D

没有 Mask：

A → A B C D
B → A B C D
C → A B C D
D → A B C D

但是 GPT 的因果注意力要求：

A → A
B → A B
C → A B C
D → A B C D

Causal Attention Mask

A

B

C

D

A

B

C

D

允许关注

禁止关注未来

教授说：

“对于每个位置，模型只能利用当前及之前的 Token 表示。”

“这样，虽然所有位置的计算可以在训练时并行完成，但每个位置仍然遵守不能看未来的约束。”

他写出代码：

seq_len = 4
mask = torch.triu(torch.ones(seq_len, seq_len, dtype=torch.bool), diagonal=1)

在 nn.MultiheadAttention 中，可以这样使用：

output, _ = attention(    x, x, x,    attn_mask=mask,    need_weights=False)

这里的 True 表示禁止关注该位置。

“注意，”教授补充，“PyTorch 不同 Attention API 对布尔 Mask 的约定不完全相同，用时要看具体接口。”

七、训练 GPT 时，Loss 怎么算？

林默很快想起第四章。

“CrossEntropyLoss？”

“没错。”

模型输出：

logits:

[B, N, V]

标签：

targets:

[B, N]

其中：

B = Batch Size
N = Sequence Length
V = Vocabulary Size

但普通的：

nn.CrossEntropyLoss()

对于二维分类 logits，通常期望：

[样本数量, 类别数量]

于是我们可以把：

[B, N, V]

变成：

[B × N, V]

标签：

[B, N]

变成：

[B × N]

代码：

loss = F.cross_entropy(    logits.reshape(-1, vocab_size),    targets.reshape(-1))

教授强调：

“这里不用手动 Softmax。”

林默立刻回答：

“因为 CrossEntropyLoss 接收原始 logits。”

“很好。”

1. 准备文本

假设我们有一段训练语料：

text = '林默走进实验室。教授正在研究PyTorch。神经网络正在学习语言。林默问教授，Transformer为什么能够生成文本？教授回答，因为模型能够预测下一个Token。'

真实大模型会使用海量文本。

但我们先让模型学习这段小语料。

为了演示方便，今天使用字符级 Tokenizer。

也就是：

一个字符 → 一个 Token

这比真正 LLM 使用的子词 Tokenizer 简单得多，但不影响我们学习模型结构。

2. 建立词表

import torch
import torch.nn as nn
import torch.nn.functional as F

chars = sorted(set(text))
vocab_size = len(chars)
stoi = {ch: i for i, ch in enumerate(chars)}
itos = {i: ch for ch, i in stoi.items()}

林默问：

“stoi 和 itos 是什么？”

教授写：

stoi：

String → Integer


itos：

Integer → String

例如：

"林" → 12
"默" → 28
"教" → 17

具体 ID 由词表排序决定。

编码：

def encode(s):
    return [stoi[c] for c in s]

解码：

def decode(ids):
    return "".join(itos[i] for i in ids)

“这样，文本就可以在字符与整数之间转换。”

3. 准备训练数据

data = torch.tensor(    encode(text),    dtype=torch.long)

然后设置：

block_size = 32
batch_size = 16

教授解释：

block_size
→ 每个训练样本的输入 Token 数量

batch_size
→ 每次训练取多少个序列片段

编写批次生成函数：

def get_batch():
    if len(data) <= block_size:
        raise ValueError("语料至少需要 block_size + 1 个 Token")
    starts = torch.randint(0, len(data) - block_size, (batch_size,))
    x = torch.stack([data[i:i + block_size] for i in starts])
    y = torch.stack([data[i + 1:i + block_size + 1] for i in starts])
    return x, y

林默观察：

x：

[B, 32]


y：

[B, 32]

两个 Tensor 形状相同。

只是目标向后错了一位。

这里随机抽取片段用于教学；大型预训练的数据流水线通常要复杂得多。

4. 构建 Transformer Block

我们继续使用上一章的 Pre-Norm 结构，但加入因果 Mask。

class TransformerBlock(nn.Module):
    def __init__(self, d_model, num_heads):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.attn = nn.MultiheadAttention(d_model, num_heads, batch_first=True)
        self.ln2 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, 4 * d_model), nn.GELU(),
            nn.Linear(4 * d_model, d_model),
        )

    def forward(self, x):
        T = x.size(1)
        causal_mask = torch.triu(
            torch.ones(T, T, device=x.device, dtype=torch.bool), diagonal=1
        )
        h = self.ln1(x)
        out, _ = self.attn(h, h, h, attn_mask=causal_mask, need_weights=False)
        x = x + out
        return x + self.ffn(self.ln2(x))

教授指着：

T = x.size(1)

“这里就是序列长度。”

“为什么每次都根据 x 取？”

林默回答：

“因为训练和生成时，输入序列长度可能不同。”

“对。”

5. 构建 Mini-GPT

终于到了核心代码。

class MiniGPT(nn.Module):
    def __init__(self, vocab_size, d_model=64, num_heads=4,
                 num_layers=2, block_size=32):
        super().__init__()
        self.block_size = block_size
        self.token_embedding = nn.Embedding(vocab_size, d_model)
        self.position_embedding = nn.Embedding(block_size, d_model)
        self.blocks = nn.Sequential(*[
            TransformerBlock(d_model, num_heads) for _ in range(num_layers)
        ])
        self.ln_f = nn.LayerNorm(d_model)
        self.lm_head = nn.Linear(d_model, vocab_size)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        if not 0 < T <= self.block_size:
            raise ValueError('Sequence length must be in [1, block_size]')
        positions = torch.arange(T, device=idx.device)
        x = self.token_embedding(idx) + self.position_embedding(positions)
        logits = self.lm_head(self.ln_f(self.blocks(x)))
        loss = None
        if targets is not None:
            # targets are ALREADY shifted by get_batch; do not shift twice.
            loss = F.cross_entropy(logits.reshape(-1, logits.size(-1)), targets.reshape(-1))
        return logits, loss

林默沉默了。

这是他第一次真正看到：

一个从 Token ID 开始，一直到整个词表预测结果的完整语言模型。

教授问：

“这段代码，有没有看不懂的？”

林默指着：

self.blocks = nn.Sequential(*[TransformerBlock(d_model, num_heads) for _ in range(num_layers)])

“这里的 * 是什么？”

教授解释：

“Python 的参数解包语法。”

例如：

layers = [    TransformerBlock(64, 4),    TransformerBlock(64, 4)]

使用：

nn.Sequential(*layers)

等价于把这些层依次传给 nn.Sequential。

所以我们就能轻松控制：

num_layers = 2

num_layers = 6

num_layers = 12

九、Mini-GPT 的每个 Tensor 形状

教授说：

“现在先不要运行。”

“我们从头到尾推一次 Shape。”

假设：

Batch Size = 16
Sequence Length = 32
Hidden Size = 64
Vocabulary Size = V

Mini-GPT 前向传播 Shape 流动

Token IDs [16, 32]
Token Embedding [16, 32, 64]
Position Embedding [32, 64]
相加（广播） [16, 32, 64]
Transformer Blocks [16, 32, 64]
Final LayerNorm [16, 32, 64]
LM Head [16, 32, V]
CrossEntropy 输入 [512, V]

林默看着：

[16, 32, V]

问：

“那是不是一批有 16 条序列，每条 32 个位置，每个位置都预测 V 个候选 Token？”

教授点头。

十八、完成文本生成函数

“我们先实现一个最简单的采样版本，不使用 Top-k 和 Top-p。”

@torch.no_grad()
def generate(model, idx, max_new_tokens, temperature=1.0, top_k=None, top_p=1.0):
    if temperature <= 0 or not 0 < top_p <= 1:
        raise ValueError('Require temperature > 0 and 0 < top_p <= 1')
    if top_k is not None and top_k < 1:
        raise ValueError('top_k must be positive')
    was_training = model.training
    model.eval()
    try:
        for _ in range(max_new_tokens):
            idx_cond = idx[:, -model.block_size:]
            logits, _ = model(idx_cond)
            logits = logits[:, -1, :] / temperature
            if top_k is not None:
                threshold = logits.topk(min(top_k, logits.size(-1))).values[:, [-1]]
                logits = logits.masked_fill(logits < threshold, float('-inf'))
            if top_p < 1:
                sorted_logits, order = logits.sort(descending=True, dim=-1)
                cumulative = sorted_logits.softmax(dim=-1).cumsum(dim=-1)
                remove = cumulative > top_p
                # Keep the first token crossing the threshold, including top-1.
                remove[:, 1:] = remove[:, :-1].clone()
                remove[:, 0] = False
                sorted_logits = sorted_logits.masked_fill(remove, float('-inf'))
                logits = torch.empty_like(logits).scatter(1, order, sorted_logits)
            next_token = torch.multinomial(logits.softmax(dim=-1), num_samples=1)
            idx = torch.cat([idx, next_token], dim=1)
    finally:
        model.train(was_training)
    return idx

二十二、KV Cache：把过去的计算结果保存起来

教授回顾上一章：

Q=XWQ Q=XW_Q

K=XWK K=XW_K

V=XWV V=XW_V

在自回归推理中，新 Token 需要关注之前的 Token。

对于此前已经计算过的 Token，它们在某一层的 Key 和 Value 可以缓存起来。

例如：

已经生成：

A B C

保存：

K_A
K_B
K_C

V_A
V_B
V_C

下一步生成 D：

只需要计算新 Token 的相关投影

然后把新的 K、V 加入缓存。

KV Cache

┌──────────────────────────┐
│ K_A  K_B  K_C  K_D      │
│ V_A  V_B  V_C  V_D      │
└──────────────────────────┘

后续新 Query 就可以关注这些历史 K/V。

Prefill
→ 更容易利用大规模并行计算
→ 计算吞吐是重要因素

Decode
→ 单步计算规模较小
→ 内存带宽和访存成本常常成为重要瓶颈

二十九、今天的五道思考题

Mini-GPT 理解测试

1. 为什么 GPT 训练时可以同时预测多个位置？

因为模型可以提前知道自己会生成什么

因为真实 Token 序列已知，使用 Causal Mask 后可并行计算各位置

因为训练时不需要 Attention

2. LM Head 的主要作用是什么？

把隐藏向量映射成词表大小的 logits

把文字分割成 Token

缓存过去的 K 和 V

3. Temperature 降低通常会造成什么效果？

增加模型参数量

让概率分布更平缓

让高概率 Token 更占优势

模型所有梯度

5. 为什么简单的自回归推理不能像训练一样，一次确定所有未来 Token？

因为未来 Token 尚未知，后续生成依赖前面生成结果

因为 GPU 不支持矩阵乘法

因为推理时不允许使用 Softmax
