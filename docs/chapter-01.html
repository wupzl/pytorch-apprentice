阅读提示：“下山”是局部近似：梯度指向局部上升最快的方向，负梯度才是下降方向；学习率过大时，更新仍可能让损失升高。这里用单个样本演示训练机制，不代表模型已学会对未知数据泛化。

凌晨两点。

林默盯着屏幕上的代码。

import torch

只有这一行。

他已经看了半个小时。

“所以……PyTorch 到底是什么？”

导师陈教授把咖啡放到桌上。

“你以前写 Java，对吧？”

“对。”

“那你应该习惯这样的世界。”

int a = 10;
int b = 20;
int c = a + b;

“变量、对象、方法、数据结构。”

林默点头。

教授打开 Python，在屏幕上敲下：

import torch

x = torch.tensor([1, 2, 3])

屏幕上出现：

tensor([1, 2, 3])

“欢迎来到 PyTorch 世界。”

“这里最基础的东西，不是 int，不是 double。”

教授指着那个单词。

Tensor。

一、Tensor 到底是什么？

林默皱眉。

“Tensor……张量？我每次看到这个词就觉得像数学论文。”

教授笑了。

“先忘掉‘张量’这个翻译。”

他在白板上写：

一个数字
5

“这是几维？”

“0维？”

“对。”

x = torch.tensor(5)

这是一个 0 维 Tensor。

接着教授写：

[1, 2, 3]

“这个呢？”

“一维数组。”

“在 PyTorch 里，就是 1 维 Tensor。”

x = torch.tensor([1, 2, 3])

然后：

[
  [1, 2, 3],
  [4, 5, 6]
]

林默马上回答：

“二维数组。”

“也就是二维 Tensor。”

x = torch.tensor([
    [1, 2, 3],
    [4, 5, 6]
])

教授继续画：

数字              0维 Tensor
数组              1维 Tensor
矩阵              2维 Tensor
一堆矩阵          3维 Tensor
一堆3维数据       4维 Tensor
...

林默突然明白了。

“所以 Tensor 可以粗略理解成——N 维数组？”

“对。”

“那不就是 NumPy 的 ndarray？”

教授停顿了一下。

“很好。”

“这就是第一个关键问题。”

二、那 PyTorch 和 NumPy 有什么区别？

教授写下：

import numpy as np

a = np.array([1, 2, 3])

然后：

import torch

b = torch.tensor([1, 2, 3])

看起来确实差不多。

加法也差不多：

a + a

和：

b + b

都得到：

[2, 4, 6]

“那 PyTorch 凭什么专门搞个 Tensor？”

教授没有回答。

而是敲下：

x = torch.tensor(
    [1.0, 2.0, 3.0],
    requires_grad=True
)

林默注意到了一个陌生参数：

requires_grad=True

“这是干什么？”

教授只说了一句话。

“让这块石头——”

“拥有记忆。”

三、会记住自己经历过什么的数字

教授继续输入：

x = torch.tensor(2.0, requires_grad=True)

y = x * x

数学上就是：

y=x2 y=x^2

如果：

x = 2

那么：

y = 4

这没什么神奇。

教授继续：

y.backward()

然后：

print(x.grad)

输出：

tensor(4.)

林默愣住了。

“4？”

“为什么是4？”

教授在白板上写：

y=x2 y=x^2

求导：

dydx=2x \frac{dy}{dx}=2x

因为：

x=2 x=2

所以：

dydx=4 \frac{dy}{dx}=4

林默看着：

x.grad

又看了看白板。

“等等。”

“你是说……”

“PyTorch 自动把导数算出来了？”

“对。”

四、真正重要的不是 Tensor，而是它背后的世界

教授重新写了一段：

x = torch.tensor(2.0, requires_grad=True)

a = x * 3
b = a + 4
y = b * b

如果只看代码：

x
↓
x * 3
↓
+ 4
↓
平方
↓
y

实际上，PyTorch 在背后悄悄建立了一张图：

        x
        │
       ×3
        │
        a
        │
       +4
        │
        b
       / \
      b   b
       \ /
        ×
        │
        y

这就是：

Computational Graph——计算图。

林默盯着图。

“所以我每进行一次运算……”

“PyTorch 都可能记录下来？”

“准确地说，当相关 Tensor 需要梯度时，PyTorch 会跟踪这些运算。”

教授指着：

requires_grad=True

“这句话相当于告诉 PyTorch：”

这个变量以后我要对它求导，你把相关计算过程记下来。

五、为什么神经网络非得求导？

林默问出了最重要的问题。

“但是训练神经网络为什么一定要求导？”

教授没有回答，而是给了他一道小学题。

“假设我要找到一个数字 w，让它满足：”

2w≈10 2w \approx 10

“答案是多少？”

“5。”

“但是假设机器不知道。”

初始：

w = 1

那么：

2 × 1 = 2

距离目标 10 很远。

于是定义一个“错误程度”：

Loss=(2w−10)2 Loss=(2w-10)^2

当：

w = 1

时：

Loss=(2−10)2=64 Loss=(2-10)^2=64

现在机器需要解决一个问题：

w 应该往哪个方向调整，才能让 Loss 变小？

林默沉默几秒。

“看 Loss 对 w 的导数？”

教授点头。

六、梯度其实就是“往哪边走”

教授画了一座山谷：

Loss
 ^
 |       *
 |      / \
 |     /   \
 |    /     \
 |   /       \
 |__/_________\____> w
          ↓
       最低点

神经网络训练，本质上是在找：

Loss 最低的位置。

而梯度告诉你：

当前位置的坡度

假设：

gradient > 0

说明往右走，Loss 变大。

所以应该：

往左走

也就是：

w = w - learning_rate * gradient

林默突然盯住了这个公式。

“等等……”

新参数
=
旧参数
-
学习率 × 梯度

教授点头。

“这就是你以后天天见到的——”

梯度下降。

七、第一次真正的“训练”

教授打开编辑器。

“现在不用任何神经网络 API。”

“我们手搓一次训练。”

目标：

y=2x y=2x

训练数据只有一个：

x = 5
y = 10

代码：

import torch

w = torch.tensor(1.0, requires_grad=True)

x = torch.tensor(5.0)
target = torch.tensor(10.0)

for i in range(10):

    y = w * x

    loss = (y - target) ** 2

    loss.backward()

    with torch.no_grad():
        w -= 0.01 * w.grad

    w.grad.zero_()

    print(w.item(), loss.item())

林默看着这段代码。

只有十几行。

但教授告诉他：

“你已经写出了一个极简版机器学习训练系统。”

八、逐行拆开

第一句：

w = torch.tensor(1.0, requires_grad=True)

w 是我们想学习的参数。

初始：

w = 1

但正确答案应该接近：

w = 2

第二步：

y = w * x

这叫：

Forward / 前向传播

拿当前参数计算预测结果。

例如：

w = 1
x = 5

y = 5

但是正确答案：

target = 10

第三步：

loss = (y - target) ** 2

计算：

预测得有多烂

这就是：

Loss Function / 损失函数

预测：

5

答案：

10

于是：

loss = 25

第四步：

loss.backward()

这一句话极其重要。

PyTorch 开始沿着计算图：

Loss
 ↑
 y
 ↑
 w

反向计算：

∂Loss∂w \frac{\partial Loss}{\partial w}

这就是：

Backward / 反向传播。

第五步：

w -= 0.01 * w.grad

根据梯度修改参数。

其中：

0.01

叫：

Learning Rate / 学习率。

第六步：

w.grad.zero_()

林默突然问：

“为什么要清零？”

教授笑了。

“这是 PyTorch 新手最容易踩的坑之一。”

九、梯度默认会累加

假设第一次：

w.grad = 3

第二次又算出：

w.grad = 4

很多初学者以为最后：

w.grad = 4

实际上 PyTorch 默认可能变成：

w.grad = 7

因为：

PyTorch 的梯度默认累加。

所以每轮训练通常需要：

optimizer.zero_grad()

或者刚才手写版本里的：

w.grad.zero_()

林默把这句话记在笔记里：

backward 之前/每轮训练要注意清梯度，否则梯度会累积。

十、为什么更新参数要 torch.no_grad()？

还有一段奇怪代码：

with torch.no_grad():
    w -= 0.01 * w.grad

教授问：

“我们修改 w 的这个操作，需要参与神经网络学习吗？”

“不需要。”

“那就没必要把它记录进计算图。”

所以：

with torch.no_grad():
    ...  # 此处只展示结构，完整代码见上下文

意思可以暂时理解成：

接下来这些计算不用追踪梯度。

这不仅减少额外记录，也避免对需要梯度的叶子 Tensor 做不合适的原地更新。

十一、第一张 PyTorch 世界地图

教授终于在黑板上画出了整套流程：

             数据
              │
              ▼
        ┌───────────┐
        │   Model   │
        │   模型     │
        └───────────┘
              │
              ▼
          prediction
            预测值
              │
              ▼
        ┌───────────┐
        │   Loss    │
        │  损失函数   │
        └───────────┘
              │
              ▼
       loss.backward()
              │
              ▼
           梯度 grad
              │
              ▼
      optimizer.step()
              │
              ▼
           更新参数
              │
              └─────────┐
                        │
                        ▼
                    下一轮训练

然后他在旁边写下 PyTorch 最核心的一套训练模板：

for x, y in dataloader:

    optimizer.zero_grad()

    pred = model(x)

    loss = loss_fn(pred, y)

    loss.backward()

    optimizer.step()

林默看着这五行。

教授说：

“以后你看到 CNN、RNN、Transformer，甚至很多大模型训练代码，外面套的骨架，本质上都逃不出这几个步骤。”

1. 清梯度
2. 前向传播
3. 算 Loss
4. 反向传播
5. 更新参数

“真正变化的，只是里面的模型越来越复杂。”

十二、林默第一次理解了 PyTorch

凌晨三点。

他重新看向：

import torch

这一次，它不再只是一个陌生的 Python 库。

他脑海里已经出现了一套完整的世界：

Tensor
   │
   ├── 保存数据
   │
   └── 参与运算
          │
          ▼
       计算图
          │
          ▼
        Loss
          │
          ▼
      backward()
          │
          ▼
       gradient
          │
          ▼

          │
          ▼

而所谓：

训练神经网络

第一次变成了一句非常朴素的话：

让模型算一次 → 看错多少 → 算出参数该往哪改 → 改一点 → 再来一次。

教授收起电脑。

“今天先到这里。”

教授停在门口。

“你现在只有一块会自动求导的石头。”

nn.Module
