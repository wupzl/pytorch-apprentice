  │
  ▼

这里有两个东西需要学习：

w —— weight，权重
b —— bias，偏置

比如：

y=2x+1 y=2x+1

当：

x=3 x=3

那么：

y=7 y=7

4       9

y=2x+1 y=2x+1

预测

算 Loss

backward

修改 w、b

再预测

w ≈ 2
b ≈ 1

“那我自己定义两个 Tensor 不就行了？”

输入 3 个数字

四、Tensor 与 Parameter

教授写下：

torch.Tensor

然后在下面写：

torch.nn.Parameter

“你可以先这么理解。”

Tensor
│
│ 普通数据
│
├── 输入数据
├── 标签
├── 中间计算结果
└── 其他数值


Parameter
│
│ 一种特殊 Tensor
│
└── 告诉模型：
    ‘我是需要训练的参数’

比如：

x = torch.tensor([1.0, 2.0, 3.0])

这个 x 通常只是：

数据。

而：

layer.weight

模型需要学习的参数。

五、Parameter 最关键的能力：注册

教授写了一个模型：

class MyModel(nn.Module):

    def __init__(self):
        super().__init__()

        self.w = nn.Parameter(torch.tensor(1.0))

然后：

model = MyModel()

再执行：

for p in model.parameters():
    print(p)

可以找到：

Parameter containing:
tensor(1., requires_grad=True)

“因为 self.w 是 Parameter，并且它被挂在 nn.Module 下面，所以 PyTorch 会把它注册为模型参数。”

教授擦掉代码，换成：

class MyModel(nn.Module):

    def __init__(self):
        super().__init__()

        self.w = torch.tensor(
            1.0,
            requires_grad=True
        )

“现在它虽然也能算梯度，但是——”

list(model.parameters())

并不会因为它只是普通 Tensor 就自动把它当作注册参数。

林默突然理解了。

requires_grad=True

解决的是：

要不要计算梯度？

而：

nn.Parameter

还承担着：

这是模型的一个正式参数，
请 nn.Module 管理它。

“对。”

教授点头。

“这个区别非常重要。”

七、模型其实是一棵树

看起来：

MyModel
│
├── fc1
│   └── Linear
│       ├── weight

│
└── fc2
    └── Linear
        ├── weight
        └── bias

所以一个大型神经网络，本质上可以看成：

Module
├── Module
│   ├── Parameter
│   └── Parameter

层层嵌套。

九、Optimizer 并不知道什么叫神经网络

这是一个很容易产生误解的地方。

很多人看到：

optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.001
)

会下意识觉得：

Adam 知道这个模型是什么，然后帮模型训练。

其实不是。

Optimizer 根本不关心：

你是不是 Transformer
你是不是 CNN
你是不是 RNN
你是不是大模型

它只拿到了一堆：

Parameter

例如：

[
    fc1.weight,
    fc1.bias,
    fc2.weight,
    fc2.bias
]

然后：

optimizer.step()

干的核心事情就是：

看看这些 Parameter 的 .grad
            ↓
按照优化算法
            ↓
修改 Parameter 的值

比如最简单的 SGD：

w=w−η∂L∂w w=w-\eta\frac{\partial L}{\partial w}

林默看着昨天自己手写的：

with torch.no_grad():
    w -= 0.01 * w.grad

再看看今天的：

optimizer.step()

突然笑了。

“原来这俩本质上是在干同一类事情。”

“对。”

optimizer.step() 可以看作把“根据梯度更新参数”这件事封装了起来。

当然 Adam 比简单 SGD 的更新规则复杂得多，但核心目标没变。

十、现在造出第一个真正的神经网络

教授说：

“开始。”

任务：

输入两个数字
↓
预测一个数字

建立模型：

import torch
import torch.nn as nn

class MyNet(nn.Module):

    def __init__(self):
        super().__init__()

        self.fc1 = nn.Linear(2, 4)
        self.fc2 = nn.Linear(4, 1)

    def forward(self, x):

        x = self.fc1(x)

        x = torch.relu(x)

        x = self.fc2(x)

        return x

林默沉默了。

“这就是……神经网络？”

“是。”

十一、拆开 __init__

先看：

self.fc1 = nn.Linear(2, 4)

意思是：

2 个输入
   │
   ▼
4 个输出

可以想象成：

x1 ─────┬────► h1
        ├────► h2
        ├────► h3
        └────► h4

x2 ─────┬────► h1
        ├────► h2
        ├────► h3
        └────► h4

每条连接都有一个 weight。

所以：

self.fc1.weight.shape

是：

torch.Size([4, 2])

为什么？

因为有：

4 个输出神经元
×
每个神经元接收 2 个输入

所以一共：

4×2=8 4\times2=8

个 weight。

另外：

self.fc1.bias.shape

是：

[4]

因为四个输出各自有一个 bias。

所以第一层总参数：

8+4=12 8+4=12

第二层：

self.fc2 = nn.Linear(4, 1)

有：

1×4=4 1\times4=4

个 weight。

加一个 bias：

4+1=5 4+1=5

整个网络：

12+5=17 12+5=17

个参数。

林默看着：

model.parameters()

突然觉得这个 API 不再神秘。

里面其实就是这 17 个可学习数值组成的参数 Tensor。

十二、forward() 是什么？

教授指向：

def forward(self, x):
    ...  # 此处只展示结构，完整代码见上下文

“模型拿到数据以后，怎么计算，就写在这里。”

例如：

x = self.fc1(x)

经过第一层：

输入
[ x1, x2 ]

     ↓ Linear

[ h1, h2, h3, h4 ]

然后：

x = torch.relu(x)

再：

x = self.fc2(x)

最终：

4维
 ↓
1维

得到预测值。

十三、为什么调用的是 model(x)？

林默突然发现一个奇怪的地方。

我们明明定义的是：

def forward(self, x):
    ...  # 此处只展示结构，完整代码见上下文

但真正使用的时候却通常写：

y = model(x)

而不是：

y = model.forward(x)

“为什么？”

教授说：

“因为 nn.Module 实现了调用机制。”

你写：

model(x)

PyTorch 会经过 Module 自己的调用流程，最终执行你的：

forward(x)

可以粗略理解成：

model(x)
   │
   ▼
Module.__call__()
   │
   ├── 一些 PyTorch 内部处理
   │
   ▼
forward(x)
   │
   ▼
结果

所以一般：

调用模型用 model(x)，不要手动直接调 model.forward(x)。

十四、但是这个网络有一个奇怪的东西

林默指着：

x = torch.relu(x)

“这个 ReLU 是干什么的？”

教授没有直接回答。

而是在黑板上写：

Linear(Linear(x)) Linear(Linear(x))

假设第一层：

h=W1x+b1 h=W_1x+b_1

第二层：

y=W2h+b2 y=W_2h+b_2

代进去：

y=W2(W1x+b1)+b2 y=W_2(W_1x+b_1)+b_2

展开：

y=W2W1x+W2b1+b2 y=W_2W_1x+W_2b_1+b_2

把：

W2W1 W_2W_1

看成新的：

W W

把：

W2b1+b2 W_2b_1+b_2

看成新的：

b b

那么：

y=Wx+b y=Wx+b

林默盯着公式。

过了几秒。

“等等……”

“两个 Linear 连起来……”

“最后还是一个 Linear？”

“对。”

“那我堆一百层 Linear——”

“如果中间什么都不加，本质上仍然只是一个线性变换。”

林默终于看向：

torch.relu(x)

“所以它是来打破线性的？”

教授点头。

“下一章的门已经出现了。”

十五、把模型真正训练起来

不过教授没有马上结束。

“先把今天所有东西拼起来。”

import torch
import torch.nn as nn

# 1. 数据
x = torch.tensor([
    [1.0, 2.0],
    [2.0, 3.0],
    [3.0, 4.0]
])

target = torch.tensor([
    [3.0],
    [5.0],
    [7.0]
])


# 2. 模型
class MyNet(nn.Module):

    def __init__(self):
        super().__init__()

        self.fc1 = nn.Linear(2, 4)
        self.fc2 = nn.Linear(4, 1)

    def forward(self, x):

        x = self.fc1(x)
        x = torch.relu(x)
        x = self.fc2(x)

        return x


model = MyNet()


# 3. 损失函数
loss_fn = nn.MSELoss()


# 4. 优化器
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.01
)


# 5. 训练
for epoch in range(1000):

    optimizer.zero_grad()

    pred = model(x)

    loss = loss_fn(pred, target)

    loss.backward()

    optimizer.step()

林默看着这段代码。

昨天所有零散的东西，终于连接起来了。

林默盯着最后一张图。

突然说道：

“所以 backward() 和 optimizer.step() 其实是完全不同的事情。”

教授停下脚步。

“说下去。”

林默慢慢整理：

loss.backward()

负责：

算梯度。

也就是：

每个参数应该往哪个方向改？

而：

optimizer.step()

负责：

根据梯度真正修改参数。

教授点头。

“非常重要。”

可以压缩成：

backward()
    ↓
算答案

step()
    ↓
执行答案

更准确地说：

backward()
→ 计算并累积梯度到 Parameter.grad

optimizer.step()
→ 根据优化算法和 Parameter.grad 更新参数

十七、三个概念终于连起来了

凌晨一点。

林默在自己的笔记最后写下：

Tensor
↓
负责装数据、参与计算


Parameter
↓
特殊 Tensor
代表模型需要学习的参数
被 Module 注册和管理
