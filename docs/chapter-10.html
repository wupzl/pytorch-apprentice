一、第一场灾难：梯度在深层网络中消失

教授没有立即讨论 Transformer。

而是重新写下第一章的公式：

y=wx y=wx

然后：

L=(y−target)2 L=(y-target)^2

“你还记得 backward() 的本质吗？”

林默回答：

“链式法则。”

“很好。”

教授写下：

x→f1→f2→f3→L x\rightarrow f_1\rightarrow f_2\rightarrow f_3\rightarrow L

如果求：

∂L∂x \frac{\partial L}{\partial x}

需要：

∂L∂x=∂L∂f3⋅∂f3∂f2⋅∂f2∂f1⋅∂f1∂x \frac{\partial L}{\partial x} = \frac{\partial L}{\partial f_3} \cdot \frac{\partial f_3}{\partial f_2} \cdot \frac{\partial f_2}{\partial f_1} \cdot \frac{\partial f_1}{\partial x}

林默点头。

“这不是之前讲过的吗？”

教授说：

“假设每一层的局部导数都是 0.5。”

那么经过一层：

0.5 0.5

经过两层：

0.52=0.25 0.5^2=0.25

经过十层：

0.510≈0.000977 0.5^{10}\approx0.000977

经过一百层：

0.5100≈7.89×10−31 0.5^{100}\approx7.89\times10^{-31}

林默愣住。

“一百层之后，几乎是零？”

“对。”

这是一个简化的标量例子。真实神经网络的梯度涉及矩阵、激活函数和复杂的计算路径，不是简单把每层梯度相乘成一个数字，但它能说明问题。

如果反向传播中的许多局部变换持续压缩梯度，就可能出现：

Vanishing Gradient——梯度消失。

反过来，如果连续放大，也可能出现：

Exploding Gradient——梯度爆炸。

于是林默终于意识到：

“我堆的 96 层 Attention，可能根本没有顺利学起来。”

教授点头。

“这正是残差连接想解决的重要问题之一。”

二、残差连接：给梯度修一条高速公路

教授在黑板上画：

普通网络：

x
       │
       ▼
   Attention
       │
       ▼
       y

然后画出另一种结构：

x ──────────────┐
       │               │
       ▼               │
   Attention           │
       │               │
       ▼               │
       + ◄─────────────┘
       │
       ▼
       y

林默指着旁边那条线。

“这是什么？”

“捷径。”

“什么意思？”

教授写下：

普通网络：

y=F(x) y=F(x)

残差网络：

y=x+F(x) \boxed{y=x+F(x)}

林默看着公式。

“就多加了一个 x？”

“对。”

“这也太简单了吧？”

教授笑了。

“恰恰是这一个加法，改变了深度神经网络的训练方式。”

三、为什么 x + F(x) 有用？

教授写：

y=x+F(x) y=x+F(x)

现在对 xx 求导：

∂y∂x=I+∂F(x)∂x \frac{\partial y}{\partial x} = I+\frac{\partial F(x)}{\partial x}

这里的 II 是恒等映射对应的单位矩阵。

如果暂时只考虑一维情况：

dydx=1+F′(x) \frac{dy}{dx} = 1+F'(x)

林默突然坐直。

“等等。”

“以前梯度只能经过 F。”

“现在多了一条导数为 1 的路径！”

教授点头。

普通网络反向传播：

Loss
  │
  ▼
F 的梯度
  │
  ▼
前一层


残差网络反向传播：

       Loss
         │
         ▼
       加法
       /  \
      /    \
     ▼      ▼
   F路径   恒等路径
     \      /
      \    /
       ▼
      前一层

恒等路径为梯度传播提供了一条额外通道。

不过教授马上补充：

“不能因此认为残差网络绝对不会出现梯度消失或爆炸。不同路径的梯度仍可能相互抵消或放大。”

“残差连接的价值在于，它通常能明显改善深层网络的优化难度。”

四、残差连接的第二个秘密：学习变化，而不是从头重建

教授换了一个角度。

“假设一个 Token 已经拥有不错的表示。”

例如：

x = “苹果手机”的上下文表示

经过某个 Attention 层后，模型只是希望：

增加一点“没电”的语义信息

普通网络：

y=F(x) y=F(x)

意味着 F 必须产生完整的新表示。

但残差网络：

y=x+F(x) y=x+F(x)

可以让：

x
│
├── 保留原来的信息
│
└── F(x) 负责补充或修正信息

例如：

x：

已经知道这是“手机”


F(x)：

补充“没电”相关信息


x + F(x)：

得到更丰富的手机表示

这只是帮助理解的类比，真实表示并不是逐项标注语义。

但设计思想非常重要：

模型不一定需要每层都重新生成全部信息，它可以在已有表示的基础上学习增量修正。

五、PyTorch 里的残差连接

教授打开编辑器：

import torch
import torch.nn as nn

class ResidualBlock(nn.Module):
    def __init__(self, dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(dim, dim), nn.ReLU(), nn.Linear(dim, dim)
        )

    def forward(self, x):
        return x + self.net(x)

林默看着：

return x + self.net(x)

“就这一句？”

“核心就是这一句。”

假设输入：

x = torch.randn(32, 128)

形状：

[32, 128]

那么：

self.net(x)

也必须输出：

[32, 128]

才能相加。

教授提醒：

最普通的恒等残差连接要求两条路径的输出形状兼容。

如果：

x:
[32, 128]

F(x):
[32, 256]

就不能直接进行这种残差相加。

某些网络会使用投影层调整维度，但 Transformer Block 通常让外部隐藏维度保持不变。

六、第二场灾难：网络里的数值开始失控

林默以为问题解决了。

他给 96 层模型加入残差连接。

然后重新训练。

但这一次，Loss 依旧不够稳定。

教授看着日志。

“你解决了梯度传播的一部分问题。”

“但是还有另外一件事。”

“你的每一层，拿到的输入数值是什么分布？”

林默一愣。

“数值分布？”

教授写：

第一层输出：

[0.1, 0.3, -0.2, 0.5]

中间某层输出可能变成：

[12.3, -18.7, 25.1, 8.4]

更深的某层：

[103.2, -87.4, 204.7, -51.8]

“这些数字只是示意，不代表所有网络都会如此。”

教授继续：

“如果不同层的激活尺度变化剧烈，优化就可能更加困难。”

“所以我们需要某种机制，控制数值尺度。”

黑板上出现：

Normalization

七、LayerNorm：让每个 Token 整理自己的数值

教授写：

nn.LayerNorm(512)

林默问：

“又一个新层？”

“对。”

“但是理解它之前，我们先做一个很简单的数学计算。”

假设一个 Token 的隐藏向量：

x=[1,2,3] x=[1,2,3]

计算平均值：

μ=1+2+33=2 \mu=\frac{1+2+3}{3}=2

然后计算方差：

σ2=(1−2)2+(2−2)2+(3−2)23=23 \sigma^2 = \frac{(1-2)^2+(2-2)^2+(3-2)^2}{3} = \frac23

标准化：

x^i=xi−μσ2+ϵ \hat{x}_i= \frac{x_i-\mu}{\sqrt{\sigma^2+\epsilon}}

忽略很小的 ϵ\epsilon，得到近似：

x^=[−1.225,0,1.225] \hat{x}=[-1.225,0,1.225]

林默看着结果。

“平均值变成零了。”

“对。”

“方差也变成接近一。”

“对。”

八、LayerNorm 不是简单把数值固定住

教授继续写：

y=γx^+β y=\gamma\hat{x}+\beta

林默发现两个新变量：

γ gamma
β beta

教授解释：

“标准化之后，模型还可以通过可学习参数调整每个特征维度的缩放和平移。”

所以 LayerNorm 内部通常也有：

weight → gamma

bias → beta

在 PyTorch 里：

ln = nn.LayerNorm(512)

可以看到：

print(ln.weight.shape)
print(ln.bias.shape)

输出：

torch.Size([512])
torch.Size([512])

林默突然想起第二章。

“它们也是 Parameter？”

“没错。”

所以：

model.parameters()

不仅包含：

Linear 的 weight、bias

还可能包含：

LayerNorm 的 weight、bias
Embedding 的 weight
Attention 的投影参数

优化器统一管理这些参数。

九、LayerNorm 究竟沿哪个维度计算？

教授写出 Transformer 中最经典的 Tensor 形状：

X.shape = [B, N, D]

例如：

[32, 128, 512]

代表：

32   → Batch Size
128  → Sequence Length
512  → Hidden Dimension

然后：

ln = nn.LayerNorm(512)
y = ln(x)

问题来了。

“它对哪一维计算均值和方差？”

林默思考片刻。

“512？”

“对。”

LayerNorm 的归一化范围

示意图：每个 Token 独立地沿隐藏特征维度计算统计量，不是把整个 Batch 混在一起。

教授说：

“对于这种输入，LayerNorm(512) 会分别处理每个样本、每个 Token 的 512 维向量。”

也就是：

Batch 1
  Token 1 → 对512维归一化
  Token 2 → 对512维归一化
  ...

Batch 2
  Token 1 → 对512维归一化
  Token 2 → 对512维归一化
  ...

不会把所有 Token 和 Batch 的数值混在一起求同一组均值、方差。

十、为什么 Transformer 常用 LayerNorm，而不是 BatchNorm？

林默突然想起第六章。

“教授，BatchNorm 不也能归一化吗？”

“当然。”

“那为什么 Transformer 里常见 LayerNorm？”

教授画出两个概念。

对比 BatchNorm LayerNorm
典型归一化范围 跨 Batch 等维度，对各通道统计 对每个样本的指定特征维度统计
是否受同批其他样本影响 训练时通常会 通常不会
训练与推理统计方式 常见实现存在差异 通常一致
常见使用场景 CNN 等 Transformer、LLM 等

教授说：

“语言模型的输入长度、批次组成可能不断变化。”

“尤其在自回归生成时，每次可能只处理一个新 Token。”

“LayerNorm 不依赖跨样本统计，因此非常适合这种场景。”

不过他又补充：

“现代大语言模型也大量使用 RMSNorm 等变体，不能简单认为所有 Transformer 都一定使用 LayerNorm。”

林默在笔记上写下：

BatchNorm 更多考虑批次等维度上的统计，LayerNorm 通常独立处理每个 Token 的特征向量。

十一、第三个问题：Attention 为什么还不够？

教授终于把上一章的 Attention 搬了出来。

Token 1
Token 2
Token 3
Token 4
    │
    ▼
Self-Attention
    │
    ▼
新的 Token 表示

“Attention 干什么？”

林默回答：

“让 Token 根据 Q、K、V 从其他 Token 聚合信息。”

“很好。”

“那它是否已经足够？”

林默犹豫了。

“好像还缺非线性处理？”

教授点头。

“这就是今天第三个核心模块。”

FFN

全称：

Feed-Forward Network

在 Transformer 中通常也称：

Position-wise Feed-Forward Network。

十二、FFN：每个 Token 自己的加工车间

教授画了两座工厂。

第一座：

Self-Attention

Token A ───┐
Token B ───┼──► 信息交换
Token C ───┼──► 上下文融合
Token D ───┘

第二座：

FFN

Token A → 自己加工

Token B → 自己加工

Token C → 自己加工

Token D → 自己加工

林默问：

“什么意思？”

教授解释：

“Self-Attention 的一个重要作用，是在不同 Token 之间交换信息。”

“FFN 则通常对每个 Token 的隐藏向量，独立应用同一套非线性变换。”

也就是说：

Attention 负责跨 Token 的信息交互，FFN 负责对每个 Token 的特征进行非线性加工。

这是一种非常实用的理解方式，并非两者功能的绝对边界。

十三、FFN 为什么要先升维，再降维？

教授写下：

nn.Linear(512, 2048)

再写：

nn.Linear(2048, 512)

林默看着数字。

“512 变 2048，再变回 512？”

“对。”

经典 FFN 的结构：

输入

512维
  │

十九、为什么叫 Pre-Norm？

教授问：

“Norm 在哪里？”

林默回答：

“Attention 和 FFN 前面。”

“所以叫 Pre-Norm。”

对应的另一种结构：

Post-Norm：

h=LN(x+Attention(x)) h=LN(x+Attention(x))

y=LN(h+FFN(h)) y=LN(h+FFN(h))

两种设计的区别：

Pre-Norm Post-Norm
LayerNorm 位置 子层前 残差相加后
残差主路径 更直接 经过后置归一化
深层优化 通常更容易稳定训练 可能更依赖初始化和训练配置
使用情况 现代 LLM 中很常见 原始 Transformer 等架构使用

教授补充：

“原始的 Transformer 采用的是 Post-Norm 结构。后来许多深层语言模型采用 Pre-Norm 或其变体。”

“不要把 Pre-Norm 理解成所有指标上都绝对更好，它主要是一个重要的优化与架构权衡。”

二十、用 PyTorch 亲手造一个 Transformer Block

林默已经迫不及待。

“教授，我们自己实现吧。”

教授打开编辑器。

“这次我们不只画结构。”

“我们真正写一个能执行的 Transformer Block。”

先做一个简化实现，使用 PyTorch 已有的多头 Attention。

"""Minimal Pre-Norm block; python examples/transformer.py."""
import torch
from torch import nn


class TransformerBlock(nn.Module):
    def __init__(self, d_model=128, num_heads=4):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.attn = nn.MultiheadAttention(d_model, num_heads, batch_first=True)
        self.ln2 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, 4 * d_model),
            nn.GELU(),
            nn.Linear(4 * d_model, d_model),
        )

    def forward(self, x, causal=False, padding_mask=None):
        h = self.ln1(x)
        mask = None
        if causal:
            n = x.size(1)
            mask = torch.triu(torch.ones(n, n, device=x.device, dtype=torch.bool), diagonal=1)
        out, _ = self.attn(h, h, h, attn_mask=mask,
                           key_padding_mask=padding_mask, need_weights=False)
        x = x + out
        return x + self.ffn(self.ln2(x))

林默看完，几乎立刻指出：

attn_out, _ = self.attn(h, h, h)

“为什么输入三个 h？”

教授回答：

“因为这是 Self-Attention。”

对应：

Query 来源：h

Key 来源：h

Value 来源：h

注意，这不是说 Q、K、V 三个投影后的向量完全相同。

nn.MultiheadAttention 内部依然会执行各自的可学习投影。

二十一、为什么 batch_first=True？

教授又指向：

batch_first=True

之前我们一直使用：

[B, N, D]

例如：

[32, 128, 512]

但 PyTorch 的 nn.MultiheadAttention 在 batch_first=False 时，三维输入通常使用：

[N, B, D]

设置：

batch_first=True

后，输入就可以使用：

[batch_size, seq_len, hidden_dim]

也就是：

[B, N, D]

这与我们前面学习的 Tensor 形状保持一致。

二十二、第一次运行 Transformer Block

教授写：

输出：

林默问：

“为什么维度没变？”

教授指向两次残差连接。

“因为这个 Block 的输入和输出，都需要保持相同的模型隐藏维度。”

具体：

输入：

[B, N, D]
[2, 10, 128]

       ↓

LayerNorm

[2, 10, 128]

       ↓

Multi-Head Attention

[2, 10, 128]

       ↓

Residual Add

[2, 10, 128]

       ↓

FFN

[2, 10, 512]
       ↓
[2, 10, 128]

       ↓

Residual Add

[2, 10, 128]

所以每个 Block 都能保持：

[B,N,D] [B,N,D]

不变。

这正是它能够被反复堆叠的重要原因。

二十三、但是这个 Block 还不能直接当 GPT

林默突然说：

“那我只要把它堆 96 层，不就做出了 GPT？”

教授摇头。

“还差一个极其关键的约束。”

“上一章我们刚讲过。”

林默很快反应过来。

“Causal Mask！”

“没错。”

刚才我们写：

attn_out, _ = self.attn(
    h, h, h,
    need_weights=False,
)

没有传入因果 Mask。

因此：

这个实现默认允许每个 Token 关注序列中其他所有 Token。

它更接近一个不带 Padding Mask 的双向 Self-Attention 模块，而不是完整的 GPT 自回归注意力层。

如果想做 GPT，需要限制：

Token 1 不能看到 2、3、4……

Token 2 不能看到 3、4……

Token 3 不能看到 4……

可以构造：

seq_len = x.size(1)
causal_mask = torch.triu(
    torch.ones(seq_len, seq_len, device=x.device, dtype=torch.bool),
    diagonal=1,
)

然后：

attn_out, _ = self.attn(
    h, h, h,
    attn_mask=causal_mask,
    need_weights=False,
)

这里布尔 attn_mask=True 的位置，在 nn.MultiheadAttention 中表示禁止关注。

教授提醒：

“不同 Attention API 的布尔 Mask 约定可能不同。以后使用 scaled_dot_product_attention 时，不能想当然地照搬这个规则。”

二十四、现在真正理解一层 Transformer 在做什么

教授指着输入句子：

经过 Tokenizer：

[我, 把, 苹果手机, 放在, 桌子, 上, ...]

Embedding：

[B, N, D]

进入一个 Transformer Block。

第一步：

对输入特征做归一化。

第二步：

把原有表示与 Attention 输出相加。

第四步：

对更新后的表示再次归一化。

第五步：

每个 Token 独立经过非线性特征变换。

第六步：

保留主路径并叠加本层的 FFN 输出。

于是：

一个 Transformer Block 完成了一轮信息交互和特征加工。

而接下来：

Block 1
   ↓
Block 2
   ↓
Block 3
   ↓
...
   ↓
Block 96

模型就能够不断构建更复杂的上下文表示。
