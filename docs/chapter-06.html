为什么神经网络喜欢 GPU，以及 PyTorch 如何管理 CPU 与 GPU 两个世界。

计算：

C=A×B C=A\times B

二、神经网络为什么喜欢矩阵？

上一章我们知道：

一个 Linear：

y=Wx+b y=Wx+b

如果：

batch_size = 32

输入：

X X

可能是：

32×100 32\times100

权重：

W W

可能：

256×100 256\times100

计算：

XWT XW^T

实际上就是：

大量矩阵乘法。

而深度学习训练中：

Linear
↓
Attention
↓
MLP
↓
Embedding
↓
Conv

大量都是：

矩阵
×
矩阵

GPU:

五、CUDA 是什么？

林默看着显卡：

“那 CUDA 又是什么？”

教授写：

CUDA

然后解释：

“简单理解。”

CUDA 是 NVIDIA 提供的一套让程序使用 GPU 计算能力的平台。

以前：

GPU 主要负责：

游戏画面
图形渲染

后来 NVIDIA 提供 CUDA：

让开发者可以：

普通程序
    ↓
调用 GPU
    ↓
执行计算

PyTorch 就利用 CUDA。

所以：

x.to("cuda")

意思：

把 Tensor 搬到支持 CUDA 的 GPU 上。

六、PyTorch 的设备 Device

教授打开 Python：

import torch

输入：

device = torch.device("cuda")

表示：

我要 GPU

但是更常见：

device = torch.device(
    "cuda" 
    if torch.cuda.is_available()
    else "cpu"
)

意思：

如果有 GPU：

cuda

否则：

cpu

七、Tensor 为什么需要搬设备？

因为默认：

Tensor → CPU

现在：

x = x.to("cuda")

再看：

cuda:0

意思：

第0号GPU

林默想：

“那输入搬过去不就行？”

教授摇头。

创建模型：

model = nn.Linear(10,3)

查看参数：

next(model.parameters()).device

输出：

因为：

模型里面：

weight
bias

也是 Tensor。

准确说：

Parameter

默认：

CPU

所以：

model.to("cuda")

发生什么？

九、.to(device) 到底搬了什么？

教授画：

原来：

CPU

model
│
├── weight
├── bias

执行：

model.to("cuda")

之后：

GPU

model
│
├── weight
├── bias

也就是说：

模型参数被移动到了 GPU。

不仅如此：

如果模型内部有：

self.layer1 = nn.Linear(...)
self.layer2 = nn.Linear(...)

所有注册的 Parameter：

都会一起移动。

因为：

nn.Module
    ↓
管理 Parameter
    ↓
统一迁移

十、为什么 Tensor 和 Model 必须在同一个设备？

教授写：

model = model.to("cuda")

x = torch.randn(1,10)

现在：

model:

GPU


x:

CPU

然后：

model(x)

会发生什么？

错误。

类似：

Expected all tensors to be on the same device

林默问：

“为什么不能自动帮我搬？”

教授说：

“因为自动搬迁会隐藏大量问题。”

例如：

你以为：

CPU → GPU

只是一下。

实际上：

PCIe传输
↓
内存复制
↓
同步

可能很慢。

PyTorch 要求你明确：

x = x.to(device)

让开发者知道：

我要发生一次设备迁移。

十一、完整 GPU 训练模板

教授写：

device = torch.device(
    "cuda"
    if torch.cuda.is_available()
    else "cpu"
)


model = MyModel()

model = model.to(device)


for x, y in dataloader:

    x = x.to(device)
    y = y.to(device)

    optimizer.zero_grad()

    pred = model(x)

    loss = loss_fn(
        pred,
        y
    )

    loss.backward()

    optimizer.step()

林默看着：

“其实核心变化只有三个？”

教授点头：

1.

model.to(device)


2.

x.to(device)


3.

y.to(device)

训练逻辑完全没变。

十二、GPU 显存里面到底放什么？

林默问：

“显存为什么这么容易爆？”

教授画：

GPU 显存：

┌──────────────────┐
│ 模型参数          │
│                  │
│ weight           │
│ bias             │
│                  │
├──────────────────┤
│ 梯度              │
│                  │
│ grad             │
│                  │
├──────────────────┤
│ optimizer状态     │
│                  │
├──────────────────┤
│ 输入数据          │
│                  │
├──────────────────┤
│ 中间激活          │
│                  │
└──────────────────┘

1. 模型参数

例如：

GPT 有：

7B 参数

每个参数：

float32：

4 byte

那么：

7×109×4 7\times10^9\times4

约：

28GB

仅参数。

2. Gradient

训练需要：

loss.backward()

所以每个参数需要保存：

weight
+
gradient

额外占空间。

3. Optimizer 状态

例如 Adam：

除了：

参数

还保存：

一阶动量

二阶动量

所以：

Adam 训练大型模型时：

显存压力很大。

4. Activation

这是很多人忽略的。

前向：

x
 ↓
Linear
 ↓
ReLU
 ↓
Linear
 ↓
Loss

反向传播需要知道：

中间结果

所以很多 activation 要保存。

Batch 越大：

输入更多
 ↓
中间结果更多
 ↓
显存增加

这也是为什么：

batch_size

经常卡显存。

十三、torch.no_grad() 到底省什么？

上一章我们见过：

with torch.no_grad():

    pred = model(x)

很多人理解：

“关闭梯度。”

不够准确。

教授写：

训练：

forward

↓

保存计算图

↓

backward需要

例如：

x
 ↓
Linear
 ↓
ReLU
 ↓
Loss

PyTorch 需要记录：

谁依赖谁

但是推理：

输入
 ↓
模型
 ↓
输出

你不会：

loss.backward()

所以：

这些东西没有意义：

计算图
梯度记录
activation缓存

于是：

with torch.no_grad():
    ...  # 此处只展示结构，完整代码见上下文

告诉 PyTorch：

不需要记录梯度相关信息。

结果：

更少显存

更快推理

十四、但是 no_grad() ≠ eval()

这是今天最容易混淆的地方。

林默写：

model.eval()

教授问：

“什么意思？”

林默：

“关闭梯度？”

“不对。”

eval() 是切换模型行为

有些层：

训练和推理行为不同。

最典型：

Dropout

BatchNorm

十五、Dropout

教授画：

训练：

神经元：

○ ○ ○ ○ ○

Dropout：

随机关闭：

○ × ○ × ○

目的：

防止模型过度依赖某些神经元。

训练时：

model.train()

Dropout 开启。

推理：

你希望：

所有神经元正常工作

所以：

model.eval()

关闭 Dropout。

十六、BatchNorm

BatchNorm 更复杂。

简单理解：

训练时：

它根据当前 batch：

计算：

均值
方差

然后归一化。

但是推理时：

没有不断变化的 batch。

所以：

训练：
使用当前batch统计


推理：
使用训练期间保存的统计量

所以：

model.eval()

会改变 BatchNorm 行为。

十七、训练和推理正确写法

训练：

model.train()


for x,y in dataloader:

    pred = model(x)

    loss = loss_fn(
        pred,
        y
    )

    loss.backward()

    optimizer.step()

推理：

model.eval()


with torch.no_grad():

    pred = model(x)

注意：

两个东西分别负责：

model.train()
model.eval()

↓

改变模型运行模式


torch.no_grad()

↓

是否记录梯度

十八、一个经典错误

错误：

model.eval()

pred = model(x)

loss = loss_fn(pred,y)

loss.backward()

为什么错？

因为：

eval()

只是：

Dropout关闭
BatchNorm切换

它没有禁止：

梯度计算

如果你不需要训练：

应该：

with torch.no_grad():
    ...  # 此处只展示结构，完整代码见上下文

另一个错误：

with torch.no_grad():

    model.train()

这也是奇怪组合。

因为：

你告诉 PyTorch：

我要训练模式

但是：

不要记录梯度

通常没有意义。

十九、完整训练/验证结构

真实项目通常：

for epoch in range(10):

    # ===== Train =====

    model.train()

    for x,y in train_loader:

        x = x.to(device)
        y = y.to(device)

        optimizer.zero_grad()

        pred = model(x)

        loss = loss_fn(
            pred,
            y
        )

        loss.backward()

        optimizer.step()



    # ===== Validation =====

    model.eval()

    with torch.no_grad():

        for x,y in val_loader:

            x = x.to(device)
            y = y.to(device)

            pred = model(x)

            loss = loss_fn(
                pred,
                y
            )

林默看着代码。

终于明白：

训练阶段：

学习
更新参数


验证阶段：

观察
不更新参数
