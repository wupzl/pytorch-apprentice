第四天。

林默刚走进实验室，就在黑板上写下昨天留下的问题：

loss = loss_fn(pred, target)

“教授。”

“我现在大概明白了。”

model(x)
   ↓
前向传播
   ↓
得到预测
   ↓
loss.backward()
   ↓
反向传播

“但中间这个 loss_fn……”

林默敲了敲黑板。

“凭什么它说模型错了，模型就错了？”

教授笑了。

“因为神经网络自己根本不知道什么叫‘正确’。”

一、模型其实没有目标

教授打开电脑：

model = nn.Sequential(
    nn.Linear(2, 4),
    nn.ReLU(),
    nn.Linear(4, 1)
)

输入：

x = torch.tensor([[2.0, 3.0]])

模型可能输出：

tensor([[7.31]])

林默问：

“7.31 是对还是错？”

“我不知道。”

“为什么？”

“因为你没告诉我正确答案。”

教授点头。

假设真实答案是：

target = 7

那么：

prediction = 7.31
target     = 7.00

差一点。

但如果真实答案：

target = 100

那就错得离谱。

所以：

模型只负责输出。

Loss Function 负责定义：这个输出到底有多糟糕。

二、Loss 就是模型世界里的“评分规则”

教授写：

模型
 ↓
prediction
 ↓
┌───────────────┐
│ Loss Function │ ← target
└───────────────┘
 ↓
Loss

比如：

预测 9.9
答案 10

Loss 应该比较小。

如果：

预测 100
答案 10

Loss 应该很大。

因此训练真正优化的，并不是：

“让模型变聪明”

这种模糊目标。

而是一个非常具体的数学目标：

min⁡θL(θ) \min_\theta L(\theta)

这里：

θ = 模型所有参数
L = Loss

训练就是：

不断调整参数 θ，让 Loss 尽可能下降。

三、第一位法官：MSE

教授写：

loss_fn = nn.MSELoss()

MSE：

Mean Squared Error

中文：

均方误差

公式：

MSE=1N∑i=1N(yi−y^i)2 MSE=\frac{1}{N}\sum_{i=1}^{N}(y_i-\hat y_i)^2

林默看到公式就皱眉。

教授把它擦掉。

“别背，先看一个例子。”

真实房价：

100
200
300

模型预测：

110
180
310

先计算误差：

预测    真实    误差

110     100     10
180     200    -20
310     300     10

然后平方：

10²  = 100
-20² = 400
10²  = 100

求平均：

100+400+1003=200 \frac{100+400+100}{3}=200

所以：

MSE = 200

林默点头。

“所以就是——”

预测和答案差多少
      ↓
平方
      ↓
取平均

“对。”

四、为什么要平方？

林默马上问：

“直接：

prediction−target prediction-target

不行吗？”

教授写：

样本 A：预测比答案高 10 → +10
样本 B：预测比答案低 10 → -10

如果直接平均：

10+(−10)2=0 \frac{10+(-10)}{2}=0

Loss：

0

林默：

“这模型明明两个都预测错了。”

“所以不能让正负误差互相抵消。”

平方之后：

10²  = 100
-10² = 100

就不会抵消。

而且大误差会受到更明显的惩罚：

误差 1  → 1
误差 2  → 4
误差 10 → 100

五、MSE 经常出现在回归问题

比如：

预测房价
预测温度
预测销量
预测耗时

输出本身就是一个连续数值：

263.72 万
18.4 ℃
1932 件
27.6 ms

这种任务叫：

Regression——回归。

典型结构：

输入特征
   ↓
神经网络
   ↓
一个连续值
   ↓
MSE(pred, target)

PyTorch：

pred = model(x)

loss = nn.MSELoss()(pred, target)

loss.backward()

到这里还比较简单。

教授擦掉黑板。

“现在进入真正容易混乱的地方。”

六、如果我要识别猫、狗、鸟呢？

现在任务：

输入：一张图片

输出类别：
0 = 猫
1 = 狗
2 = 鸟

林默说：

“最后输出一个数字不就好了？”

猫 → 0
狗 → 1
鸟 → 2

教授问：

“那模型预测 1.7 是什么？”

“……”

“70% 鸟？”

“不知道。”

更麻烦的是：

猫 = 0
狗 = 1
鸟 = 2

如果直接使用数值距离，就隐含了：

猫到狗距离 = 1
狗到鸟距离 = 1
猫到鸟距离 = 2

但类别编号只是标签。

猫并不因为编号是 0，就比编号为 2 的鸟离狗更远。

所以分类不能简单把类别编号当连续数值做回归。

七、分类模型应该输出多个数字

三个类别：

猫
狗
鸟

那么模型最后输出：

nn.Linear(hidden_size, 3)

也就是：

[2.1, 5.7, -1.3]

林默看着三个数字。

“这三个是什么意思？”

教授说：

“它们有一个名字。”

Logits

八、Logits 是什么？

假设：

猫： 2.1
狗： 5.7
鸟：-1.3

可以粗略理解：

模型更倾向狗

因为：

5.7 最大

所以预测类别：

predicted_class = logits.argmax(dim=1)

得到：

狗

但是注意：

2.1
5.7
-1.3

不是概率。

因为概率通常应该满足：

0 ≤ p ≤ 1

而且：

所有类别概率之和 = 1

这里显然不是。

于是教授写下：

Softmax

九、Softmax：把分数变成概率分布

Softmax 做的事情，可以暂时理解成：

任意 logits

[2.1, 5.7, -1.3]

        ↓ Softmax

合法概率分布

[0.027, 0.972, 0.001]

满足：

每个数在 0~1 之间

并且

0.027 + 0.972 + 0.001 = 1

于是：

猫：  2.7%
狗： 97.2%
鸟：  0.1%

现在就很好理解了。

十、Softmax 怎么做到的？

教授终于写公式：

Softmax(zi)=ezi∑jezj Softmax(z_i)=\frac{e^{z_i}}{\sum_j e^{z_j}}

林默皱眉。

“又开始了。”

“别看公式，直接算。”

假设 logits：

[1, 2, 3]

先指数：

e1≈2.72 e^1\approx2.72

e2≈7.39 e^2\approx7.39

e3≈20.09 e^3\approx20.09

总和：

30.20 30.20

所以：

类别0：
2.72 / 30.20 ≈ 0.09

类别1：
7.39 / 30.20 ≈ 0.245

类别2：
20.09 / 30.20 ≈ 0.665

最终：

[0.09, 0.245, 0.665]

刚好：

总和 = 1

十一、Softmax 真正重要的是“相对竞争”

教授突然问：

“如果 logits 是：”

[1, 2, 3]

“第三类概率最高。”

“那如果全部加 100 呢？”

[101, 102, 103]

林默想了一会。

“第三类还是最高。”

不仅如此。

Softmax 的结果实际上不会改变。

因为：

Softmax(z+c)=Softmax(z) Softmax(z+c)=Softmax(z)

所以 Softmax 真正关心的是：

类别之间的相对差距。

而不是某个 logit 自己绝对有多大。

十二、现在来了第二位法官：Cross Entropy

假设真实答案：

狗

也就是：

target = 1

模型 Softmax 后：

猫：0.10
狗：0.80
鸟：0.10

这个预测挺好。

如果：

猫：0.49
狗：0.02
鸟：0.49

这个预测就非常糟糕。

Cross Entropy 的核心思想可以先理解为：

看看模型给“正确类别”分配了多大概率。

正确类别是狗。

第一种：

P(狗) = 0.80

不错。

第二种：

P(狗) = 0.02

很差。

十三、为什么还要取 -log？

对于单个样本的多分类问题，可以先看成：

Loss=−log⁡(p正确类别) Loss=-\log(p_{\text{正确类别}})

假设正确答案是狗。

如果模型：

P(狗) = 0.9

那么：

−log⁡(0.9)≈0.105 -\log(0.9)\approx0.105

Loss 很小。

如果：

P(狗)=0.5

那么：

−log⁡(0.5)≈0.693 -\log(0.5)\approx0.693

更大。

如果：

P(狗)=0.01

那么：

−log⁡(0.01)≈4.605 -\log(0.01)\approx4.605

巨大。

所以：

正确类别概率

1.0 ─────────────→ Loss 接近 0

0.8 ─────────────→ Loss 较小

0.5 ─────────────→ Loss 变大

0.1 ─────────────→ Loss 很大

0.01 ────────────→ Loss 巨大

教授说：

“尤其是——”

如果模型非常自信地预测错了，会受到很重的惩罚。

十四、整个分类链路终于出现了

黑板上出现：

                输入图片
                   │
                   ▼
                 Model
                   │
                   ▼
                 logits
                   │
          [2.1, 5.7, -1.3]
                   │
                   ▼
                Softmax
                   │
                   ▼
         [0.027, 0.972, 0.001]
                   │
                   ▼
       看正确类别对应的概率
                   │
                   ▼
                 -log
                   │
                   ▼
                  Loss

林默点头。

“那 PyTorch 应该这么写？”

softmax = nn.Softmax(dim=1)

prob = softmax(model(x))

loss = nn.CrossEntropyLoss()(prob, target)

教授突然停住。

“错。”

林默：“？”

“这是今天最重要的坑。”

十五、CrossEntropyLoss 前面不要自己加 Softmax

PyTorch 中：

loss_fn = nn.CrossEntropyLoss()

通常直接这样：

logits = model(x)

loss = loss_fn(logits, target)

而不是：

prob = torch.softmax(logits, dim=1)

loss = loss_fn(prob, target)

为什么？

因为：

nn.CrossEntropyLoss() 期望输入的是原始 logits。

它内部已经把所需的 LogSoftmax 和 NLLLoss 组合起来了。

可以概念化成：

CrossEntropyLoss

≈

LogSoftmax
+
NLLLoss

所以：

loss = nn.CrossEntropyLoss()(
    logits,
    target
)

内部已经完成了对应计算。

十六、为什么 PyTorch 要这么设计？

林默问：

“直接 Softmax 再 log 不就行了吗？”

教授写：

logits
 ↓
Softmax
 ↓
log

数学上能推。

但实际计算机使用有限精度浮点数。

假设某个类别概率极小：

0.000000000000000000000000000001

数值计算可能出现精度问题。

因此实际实现通常会通过更稳定的数学形式计算。

所以 PyTorch 让你直接提供：

logits

它内部做数值稳定处理。

因此要形成条件反射：

nn.CrossEntropyLoss()

配：

raw logits

训练时通常不要在前面手动 Softmax。

十七、那什么时候用 Softmax？

林默懵了。

“那 torch.softmax() 岂不是没用了？”

“当然不是。”

训练算 Loss：

logits = model(x)

loss = loss_fn(logits, target)

但是推理时，如果你想看到：

猫：2%
狗：97%
鸟：1%

可以：

with torch.no_grad():

    logits = model(x)

    probs = torch.softmax(
        logits,
        dim=1
    )

所以：

训练算 CrossEntropyLoss
        ↓
直接使用 logits


需要查看类别概率
        ↓
Softmax(logits)

十八、dim=1 又是什么鬼？

林默盯着：

torch.softmax(logits, dim=1)

“为什么是 1？”

教授把 Tensor 形状写出来：

batch_size = 4
num_classes = 3

模型输出：

shape = [4, 3]

比如：

[
  [2.1, 5.7, -1.3],   ← 样本1
  [3.2, 1.1,  0.7],   ← 样本2
  [0.1, 0.3,  4.2],   ← 样本3
  [1.2, 1.9,  0.4]    ← 样本4
]

维度：

dim=0
  ↓
不同样本之间

dim=1
  ↓
一个样本的不同类别之间

我们希望：

每一个样本内部
猫 + 狗 + 鸟
概率和 = 1

所以：

torch.softmax(logits, dim=1)

也就是：

沿着类别维度做 Softmax。

十九、这时候 Tensor 的 Shape 开始变得危险

教授突然问：

“模型输出是什么 shape？”

[batch_size, num_classes]

“target 呢？”

林默试探：

[batch_size, 1]？

“不。”

对于常见的多分类 CrossEntropyLoss 类别索引标签，通常是：

[batch_size]

例如：

logits = torch.tensor([
    [2.1, 5.7, -1.3],
    [3.2, 1.1,  0.7],
    [0.1, 0.3,  4.2]
])

shape：

[3, 3]

target：

target = torch.tensor([
    1,
    0,
    2
])

意思：

样本1正确答案：类别1
样本2正确答案：类别0
样本3正确答案：类别2

shape：

[3]

而且类别索引 target 通常应该是：

torch.long

不是 float。

二十、第一个完整分类模型

教授终于写出：

import torch
import torch.nn as nn

model = nn.Sequential(

    nn.Linear(10, 32),

    nn.ReLU(),

    nn.Linear(32, 3)
)

注意最后：

nn.Linear(32, 3)

后面没有：

nn.Softmax()

因为训练使用：

loss_fn = nn.CrossEntropyLoss()

完整训练：

optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.001
)

for epoch in range(100):

    optimizer.zero_grad()

    logits = model(x)

    loss = loss_fn(
        logits,
        target
    )

    loss.backward()

    optimizer.step()

预测：

with torch.no_grad():

    logits = model(x)

    pred = logits.argmax(dim=1)

甚至如果只想知道哪个类别最大：

根本不需要 Softmax。

因为 Softmax 不会改变 logits 的大小排序。

所以：

logits.argmax(dim=1)

和：

torch.softmax(logits, dim=1).argmax(dim=1)

预测类别相同。

二十一、林默突然发现一个大问题

他看着：

loss.backward()

突然问：

“教授。”

“我们刚才不是有：

Linear
↓
ReLU
↓
Linear
↓
CrossEntropy
↓
Loss

吗？”

“对。”

“那 loss.backward() 是不是会从 CrossEntropy 开始……”

然后：

Loss
 ↑
CrossEntropy
 ↑
最后一个 Linear
 ↑
ReLU
 ↑
第一个 Linear

“一层一层往回算导数？”

教授没有说话。

林默继续：

“比如最后一层参数对 Loss 的影响。”

“然后上一层参数通过最后一层间接影响 Loss。”

“所以要用……”

他在黑板上写：

∂L∂w \frac{\partial L}{\partial w}

接着又写：

∂L∂y∂y∂h∂h∂w \frac{\partial L}{\partial y} \frac{\partial y}{\partial h} \frac{\partial h}{\partial w}

教授终于笑了。

“你已经走到 PyTorch 最核心的地方了。”

二十二、链式法则

假设：

x→a→b→Loss x\rightarrow a\rightarrow b\rightarrow Loss

其中：

a=f(x) a=f(x)

b=g(a) b=g(a)

L=h(b) L=h(b)

如果要求：

dLdx \frac{dL}{dx}

数学上：

dLdx=dLdb⋅dbda⋅dadx \frac{dL}{dx} = \frac{dL}{db} \cdot \frac{db}{da} \cdot \frac{da}{dx}

这就是：

Chain Rule——链式法则。

林默突然意识到：

“所以反向传播不是一种神秘的 AI 算法？”

“不是。”

反向传播的数学核心，就是利用链式法则高效地计算梯度。

而 PyTorch 的 Autograd，则替你记录计算关系，并完成这些梯度计算。

二十三、昨天那个问题终于彻底回答了

第一章的时候，林默问：

“反向传播其实就是计算导数吗？”

现在教授给出了更准确的答案：

可以这么理解，但要再精确一点：

反向传播是在计算图上，从最终 Loss 出发，利用链式法则反向传播梯度，高效计算各个需要梯度的参数对 Loss 的导数。

也就是：

↓

算梯度
↑
算梯度
↑
算梯度
↑
算梯度
↑
Parameter.grad

最后，每一个 Parameter 身上都有：

param.grad

然后：

optimizer.step()

读取这些梯度，修改参数。
