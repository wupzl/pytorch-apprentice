第九天。

教授没有打开代码。

他只在黑板上写了一句话：

我把苹果手机放在桌子上，因为它没电了。

然后问：

“这里的‘它’指什么？”

林默几乎没思考：

“苹果手机。”

“为什么不是桌子？”

“因为‘没电’和手机更相关。”

教授点头。

“很好。”

“人类读一句话时，不是机械地一个词一个词孤立理解。”

“你会让当前这个词，去参考上下文里其他词。”

他在黑板上写下：

Attention

一、Attention 最朴素的想法

假设当前正在处理：

它

那么模型可能会看看：

我
把
苹果手机
放在
桌子
上
因为
它
没电
了

并给不同词不同关注程度。

比如：

苹果手机  0.55
没电      0.25
桌子      0.03
我        0.02
...

于是：

当前 Token 的新表示，不再只由自己决定，而是会融合上下文信息。

这就是 Attention 的核心。

二、Self-Attention 为什么叫“Self”

教授问：

“谁在关注谁？”

林默回答：

“句子里的 Token 互相关注？”

“对。”

输入序列内部：

Token 1
Token 2
Token 3
...
Token n

每个 Token 都可以去关注同一序列里的其他 Token。

所以叫：

Self-Attention

也就是：

序列自己看自己。

三、但模型怎么知道“该关注谁”？

教授在黑板上写出三个字母：

Q

K

V

林默皱眉。

“终于来了。”

教授笑了。

“很多人就是从这里开始把 Attention 背成公式。”

“今天别背。”

四、先把 Q、K、V 想成搜索系统

教授说：

“你做过 RAG，对吧？”

林默点头。

“假设你现在有一个 query：”

Java HashMap 为什么线程不安全？

你会拿 query 去跟文档里的内容匹配。

比如：

文档A：HashMap 扩容机制
文档B：ConcurrentHashMap
文档C：Spring IOC

然后判断：

Query 和 A 相关程度？
Query 和 B 相关程度？
Query 和 C 相关程度？

Attention 也有点类似。

对于当前 Token：

我现在想找什么？

这就是：

Query

简称：

Q

五、Key 是什么？

每个被搜索的 Token 都提供一个：

“我有什么特征，可以被别人匹配？”

这就是：

Key

简称：

K

比如当前：

它

生成的 Q 可能表达：

“我现在需要找一个可能被‘没电’修饰的对象。”

而：

苹果手机

的 K 可能表达：

“我是电子设备相关实体。”

桌子对应的 K：

“我是家具。”

那么：

Q(它)

和：

K(苹果手机)

匹配度很高。

跟：

K(桌子)

匹配度很低。

六、那 V 又是什么？

教授问：

“如果已经发现苹果手机最相关，接下来怎么办？”

林默说：

“把苹果手机的信息拿过来。”

“对。”

每个 Token 不仅有：

Key

还带着真正想传递给别人的：

Value

简称：

V

所以：

Q
→ 我想找谁？

K
→ 我适不适合被你找到？

V
→ 如果你关注我，我真正给你什么信息？

七、一个生活化比喻

教授画了一座图书馆。

你手里拿着问题：

我要找 PyTorch 自动求导相关资料

这就是：

Q

每本书封面上的关键词：

深度学习
PyTorch
Java
数据库
Autograd

类似：

K

而书里面真正的正文：

V

搜索流程：

Query
 ↓
和各个 Key 比较
 ↓
得到相关度
 ↓
按照相关度
 ↓
读取不同 Value
 ↓
综合得到结果

林默马上说：

“这和向量检索确实很像。”

“对，但 Attention 是在模型内部动态完成的。”

八、Q、K、V 是怎么来的？

教授把上章输出拿出来。

经过 Embedding 后：

x
shape:
[batch, seq_len, hidden_dim]

例如：

[1, 5, 512]

意思：

1 个句子
5 个 Token
每个 Token 512 维

然后模型拥有三组可学习矩阵：

WQ, WK, WV W_Q,\ W_K,\ W_V

计算：

Q=XWQ Q=XW_Q

K=XWK K=XW_K

V=XWV V=XW_V

林默问：

“又是 Linear？”

“对。”

PyTorch 里完全可以理解成：

self.q_proj = nn.Linear(hidden_dim, head_dim)
self.k_proj = nn.Linear(hidden_dim, head_dim)
self.v_proj = nn.Linear(hidden_dim, head_dim)

所以：

Q、K、V 并不是凭空出现的。

它们是：

同一个输入表示，经过三种不同的可学习线性投影得到的。

九、为什么同一个 Token 要生成三个版本？

林默问：

“直接用原始 Embedding 比不行吗？”

教授说：

“因为同一个 Token 在 Attention 中承担三种角色。”

比如：

苹果手机

作为 Query：

我现在想找什么信息？

作为 Key：

别人为什么应该关注我？

作为 Value：

如果别人关注我，我提供什么信息？

这三种角色不一定需要使用同一个向量空间。

所以模型学习：

W_Q
W_K
W_V

把原始表示变成三套不同表示。

十、Q 和 K 怎么算相关性？

教授写出最核心的一步：

QKT QK^T

林默：

“矩阵乘法？”

“对。”

先看一个 Token。

假设：

Q = [1, 2]

苹果手机的：

K1 = [1, 3]

桌子的：

K2 = [-1, 0]

点积：

Q⋅K1=1×1+2×3=7 Q\cdot K_1 = 1\times1+2\times3 = 7

而：

Q⋅K2=1×(−1)+2×0=−1 Q\cdot K_2 = 1\times(-1)+2\times0 = -1

于是：

苹果手机：7
桌子：-1

很自然：

苹果手机相关性更高。

十一、点积到底代表什么？

两个向量：

a⋅b a\cdot b

可以写成：

∣a∣∣b∣cos⁡θ |a||b|\cos\theta

所以当方向更相似：

点积通常更大

在 Attention 里：

Query 和 Key 点积越大，可以理解为它们越匹配。

因此：

Q × K^T

会一次性算出：

每个 Query 和所有 Key 的匹配分数。

十二、整个 Attention Score 矩阵

假设有 4 个 Token：

A
B
C
D

每个 Token 都生成：

Q
K

那么：

QKT QK^T

会得到一个：

4 × 4

矩阵：

          K_A   K_B   K_C   K_D

Q_A       2.1   0.3   1.7   0.1

Q_B       0.2   3.4   0.8   1.1

Q_C       1.9   0.7   2.5   0.4

Q_D       0.1   1.2   0.5   3.1

每一行：

一个 Token 在看所有 Token。

例如：

Q_C

这一行：

C 对 A 的关注分数
C 对 B 的关注分数
C 对 C 的关注分数
C 对 D 的关注分数

十三、为什么还要除以 √d？

教授终于写完整：

QKTdk \frac{QK^T}{\sqrt{d_k}}

林默问：

“这个 √d 到底是干嘛？”

教授说：

“如果向量维度很大，点积容易变得很大。”

比如：

维度只有 2：

点积可能：
2
5
-3

维度变成 512：

很多项加起来。

结果可能：

50
100
-70

然后 Softmax：

[50, 100, -70]

会变得极端：

≈ [0, 1, 0]

一旦 Softmax 太饱和：

梯度可能变得很小。

所以除以：

dk \sqrt{d_k}

把数值缩小到更稳定的范围。

这就是：

Scaled Dot-Product Attention

里的：

Scaled

十四、为什么要 Softmax？

现在得到：

scores:

[2.1, 5.7, 0.3, -1.2]

这还不是权重。

于是：

weights = torch.softmax(scores, dim=-1)

变成：

[0.026, 0.934, 0.037, 0.003]

满足：

所有权重 ≥ 0

并且

总和 = 1

于是这些数字可以解释成：

当前 Token 应该从不同 Token 那里拿多少信息。

十五、最后为什么乘 V？

教授写：

Attention(Q,K,V)=softmax(QKTdk)V Attention(Q,K,V) = softmax\left( \frac{QK^T}{\sqrt{d_k}} \right)V

林默终于能拆了。

第一部分：

QKT QK^T

回答：

谁和谁相关？

第二部分：

Softmax

回答：

每个人应该占多少权重？

第三部分：

× V

回答：

按照这些权重，把真正的信息混合起来。

十六、一个极简例子

假设三个 Token：

桌子
没电

对于：

“它”

Attention 权重：

苹果手机：0.7

对应 Value：

V_手机
V_桌子

那么输出：

0.7V手机+0.1V桌子+0.2V没电 0.7V_{\text{手机}} + 0.1V_{\text{桌子}} + 0.2V_{\text{没电}}

所以：

“它”的新表示中，包含了大量手机信息，也融合了一部分“没电”的上下文。

这就是：

Contextual Representation

十七、Self-Attention 真正改变了 Token

进入 Attention 前：

“苹果”

可能只有基础表示：

苹果这个 Token 的初始向量

但是经过 Attention：

在：

苹果很好吃

中：

会融合：

吃
好吃

的信息。

在：

苹果发布了新款 Mac

中：

会融合：

发布
Mac

的信息。

所以最终：

苹果

的表示会因上下文不同而不同。

这就是上一章说的：

上下文化表示。

十八、PyTorch 手写一个最小 Attention

教授终于打开代码：

import torch
import torch.nn.functional as F

Q = torch.randn(4, 8)
K = torch.randn(4, 8)
V = torch.randn(4, 8)

scores = Q @ K.T

scores = scores / (8 ** 0.5)

weights = F.softmax(scores, dim=-1)

output = weights @ V

林默问：

“shape 是什么？”

教授写：

Q: [4, 8]
K: [4, 8]
V: [4, 8]

那么：

K.T
→ [8, 4]

所以：

Q @ K.T

[4,8] × [8,4]

→ [4,4]

也就是：

Attention Score Matrix

再：

weights @ V

[4,4] × [4,8]

→ [4,8]

最后：

每个 Token 仍然得到一个 8 维向量。

十九、加上 Batch 之后

真实模型不会只有一句话。

假设：

batch_size = 32
seq_len = 128
hidden_dim = 512

输入：

X:

[32, 128, 512]

生成 Q/K/V 后：

Q:
[32, 128, 512]

K:
[32, 128, 512]

V:
[32, 128, 512]

计算：

Q @ K^T

注意最后两个维度：

[128,512]
×
[512,128]

得到：

[32,128,128]

也就是说：

每个 batch 中：

128 个 Token
×
128 个 Token

互相计算相关性。

二十、O(n²) 从哪来的？

教授在黑板上圈住：

[seq_len, seq_len]

假设：

seq_len = n

Attention Matrix：

n × n

所以计算和内存开销的重要部分会随：

n2 n^2

增长。

例如：

n = 1,000

attention matrix:
1,000,000

如果：

n = 10,000

变成：

100,000,000

不是增长 10 倍。

而是：

100 倍。

这就是经典 Self-Attention 长上下文昂贵的重要原因。

二十一、为什么不是只看附近？

林默问：

“那为什么不只看前后几个 Token？”

教授说：

“那当然可以设计。”

比如 CNN 或局部 Attention 就会限制感受范围。

但标准 Self-Attention 的强大之处之一就是：

任意两个位置，可以直接建立联系。

例如：

序列开头：
张三今天来到北京……

中间几千字……

最后：
他决定回家。

“他”可以直接关注很远之前的“张三”。

路径长度近似：

1

而不是一层一层传过去。

这也是 Transformer 相比很多早期序列模型的重要优势。

二十二、但是一个 Attention 头够吗？

教授写一句：

小明去银行存了钱，回来的路上坐在河岸边。

“银行”和“河岸”的 bank 是不同含义。

模型处理语言时，可能同时需要关注：

语法关系
语义关系
指代关系
位置关系
实体关系
长距离依赖

如果只有一套：

Q/K/V

相当于只有一种关注视角。

于是 Transformer 做了一件事：

同时开多个观察窗口。

这就是：

Multi-Head Attention

二十三、多头注意力是什么？

假设：

hidden_dim = 512
num_heads = 8

那么：

head_dim = 512 / 8 = 64

把表示拆成：

Head 1 → 64维
Head 2 → 64维
Head 3 → 64维
...
Head 8 → 64维

每个 Head 都有自己的：

Q
K
V

于是：

Head 1
可能重点学习语法关系

Head 2
可能重点学习实体关系

Head 3
可能重点学习位置关系

...

注意：

这只是帮助理解。

现实中不能简单认定：

某个头一定就是“语法头”或“指代头”。

不同模型内部机制会更复杂。

二十四、多头怎么合回来？

每个 Head 输出：

[batch, seq_len, head_dim]

8 个 Head：

8 × 64 = 512

拼接：

Concat

得到：

[batch, seq_len, 512]

再经过：

W_O

一个输出投影。

所以整体：

X
 ↓
分成多个 Head
 ↓
各自 Attention
 ↓
Concat
 ↓
Linear
 ↓
输出

二十五、PyTorch 里的形状变换

教授写：

假设：

X:
[B, N, D]

其中：

B = batch
N = seq_len
D = hidden_dim

例如：

[32,128,512]

8 头：

H = 8
head_dim = 64

会 reshape：

[32,128,512]
↓
[32,128,8,64]

然后通常 transpose：

[32,8,128,64]

为什么？

因为我们希望：

每个 Batch
里面
每个 Head
独立计算
128×128 的 Attention

所以：

Q:
[B,H,N,d]

K:
[B,H,N,d]

V:
[B,H,N,d]

二十六、真正的多头 Attention

计算：

QKT QK^T

shape：

[B,H,N,d]
×
[B,H,d,N]

→

[B,H,N,N]

于是：

每个 Batch
每个 Head

都有一个：

N × N

Attention Matrix

然后：

softmax

再乘：

V

得到：

[B,H,N,d]

再把 Heads 合并回：

[B,N,D]

二十七、那 Decoder 为什么不能看未来？

教授突然写一句：

我 喜欢 吃 苹果

训练语言模型时：

当预测：

喜欢

的时候，

如果让模型直接看到：

吃 苹果

那就是作弊。

就像考试的时候：

答案直接印在后面。

所以 GPT 这种自回归语言模型还需要：

Causal Mask

二十八、Causal Mask

假设有四个 Token：

A B C D

标准 Self-Attention：

在 Softmax 之前。

三十一、一个真正接近 Transformer 的 Attention 模块

教授写：

import torch
import torch.nn as nn
import torch.nn.functional as F


class SelfAttention(nn.Module):

    def __init__(self, hidden_dim):
        super().__init__()

        self.q_proj = nn.Linear(
            hidden_dim,
            hidden_dim
        )

        self.k_proj = nn.Linear(
            hidden_dim,
            hidden_dim
        )

        self.v_proj = nn.Linear(
            hidden_dim,
            hidden_dim
        )

    def forward(self, x):

        Q = self.q_proj(x)
        K = self.k_proj(x)
        V = self.v_proj(x)

        d = Q.size(-1)

        scores = (
            Q @ K.transpose(-2, -1)
        ) / (d ** 0.5)

        weights = F.softmax(
            scores,
            dim=-1
        )

        output = weights @ V

        return output

三十二、公式现在可以读成人话了

经典公式：

Attention(Q,K,V)=softmax(QKTdk)V Attention(Q,K,V) = softmax \left( \frac{QK^T}{\sqrt{d_k}} \right)V

↓
当前 Token 想找什么


K
↓
其他 Token 提供什么匹配特征


QKᵀ
↓
两两计算匹配程度


÷ √d
↓
防止数值过大


Softmax
↓
把匹配分数变成注意力权重


× V
↓
按照权重把信息聚合回来
