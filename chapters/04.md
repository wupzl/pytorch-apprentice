## 二、Loss 就是模型世界里的“评分规则”

教授写：

```text
模型
 ↓
prediction
 ↓
┌───────────────┐
│ Loss Function │ ← target
└───────────────┘
 ↓
Loss
```

比如：

```text
预测 9.9
答案 10
```

Loss 应该比较小。

如果：

```text
预测 100
答案 10
```

Loss 应该很大。

因此训练真正优化的，并不是：

```text
“让模型变聪明”
```

这种模糊目标。

而是一个非常具体的数学目标：

\[
\min_\theta L(\theta)
\]

这里：

```text
θ = 模型所有参数
L = Loss
```

训练就是：

> **不断调整参数 θ，让 Loss 尽可能下降。**

## 三、第一位法官：MSE

教授写：

```python
loss_fn = nn.MSELoss()
```

MSE：

> **Mean Squared Error**

中文：

> **均方误差**

公式：

\[
MSE=\frac{1}{N}\sum_{i=1}^{N}(y_i-\hat y_i)^2
\]

林默看到公式就皱眉。

教授把它擦掉。

“别背，先看一个例子。”

真实房价：

```text
100
200
300
```

模型预测：

```text
110
180
310
```

先计算误差：

```text
预测    真实    误差

110     100     10
180     200    -20
310     300     10
```

然后平方：

```text
10²  = 100
-20² = 400
10²  = 100
```

求平均：

\[
\frac{100+400+100}{3}=200
\]

所以：

```text
MSE = 200
```

林默点头。

“所以就是——”

```text
预测和答案差多少
      ↓
平方
      ↓
取平均
```

“对。”

## 四、为什么要平方？

林默马上问：

“直接：

\[
prediction-target
\]

不行吗？”

教授写：

```text
样本 A：预测比答案高 10 → +10
样本 B：预测比答案低 10 → -10
```

如果直接平均：

\[
\frac{10+(-10)}{2}=0
\]

Loss：

```text
0
```

林默：

“这模型明明两个都预测错了。”

“所以不能让正负误差互相抵消。”

平方之后：

```text
10²  = 100
-10² = 100
```

就不会抵消。

而且大误差会受到更明显的惩罚：

```text
误差 1  → 1
误差 2  → 4
误差 10 → 100
```

## 八、Logits 是什么？

假设：

```text
猫： 2.1
狗： 5.7
鸟：-1.3
```

可以粗略理解：

```text
模型更倾向狗
```

因为：

```text
5.7 最大
```

所以预测类别：

```python
predicted_class = logits.argmax(dim=1)
```

得到：

```text
狗
```

但是注意：

```text
2.1
5.7
-1.3
```

**不是概率。**

因为概率通常应该满足：

```text
0 ≤ p ≤ 1
```

而且：

```text
所有类别概率之和 = 1
```

这里显然不是。

于是教授写下：

### Softmax

## 九、Softmax：把分数变成概率分布

Softmax 做的事情，可以暂时理解成：

```text
任意 logits

[2.1, 5.7, -1.3]

        ↓ Softmax

合法概率分布

[0.027, 0.972, 0.001]
```

满足：

```text
每个数在 0~1 之间

并且

0.027 + 0.972 + 0.001 = 1
```

于是：

```text
猫：  2.7%
狗： 97.2%
鸟：  0.1%
```

现在就很好理解了。

## 十、Softmax 怎么做到的？

教授终于写公式：

\[
Softmax(z_i)=\frac{e^{z_i}}{\sum_j e^{z_j}}
\]

林默皱眉。

“又开始了。”

“别看公式，直接算。”

假设 logits：

```text
[1, 2, 3]
```

先指数：

\[
e^1\approx2.72
\]

\[
e^2\approx7.39
\]

\[
e^3\approx20.09
\]

总和：

\[
30.20
\]

所以：

```text
类别0：
2.72 / 30.20 ≈ 0.09

类别1：
7.39 / 30.20 ≈ 0.245

类别2：
20.09 / 30.20 ≈ 0.665
```

最终：

```text
[0.09, 0.245, 0.665]
```

刚好：

```text
总和 = 1
```

---

## 十一、Softmax 真正重要的是“相对竞争”

教授突然问：

“如果 logits 是：”

```text
[1, 2, 3]
```

“第三类概率最高。”

“那如果全部加 100 呢？”

```text
[101, 102, 103]
```

林默想了一会。

“第三类还是最高。”

不仅如此。

Softmax 的结果实际上不会改变。

因为：

\[
Softmax(z+c)=Softmax(z)
\]

所以 Softmax 真正关心的是：

> **类别之间的相对差距。**

而不是某个 logit 自己绝对有多大。

## 十二、现在来了第二位法官：Cross Entropy

假设真实答案：

```text

```

也就是：

```text

```

模型 Softmax 后：


这个预测挺好。

如果：

```text

狗：0.02
鸟：0.49
```

这个预测就非常糟糕。

Cross Entropy 的核心思想可以先理解为：

> **看看模型给“正确类别”分配了多大概率。**

正确类别是狗。

第一种：

```text
P(狗) = 0.80
```

不错。

第二种：

```text
P(狗) = 0.02
```

很差。

## 十三、为什么还要取 `-log`？

对于单个样本的多分类问题，可以先看成：

\[
Loss=-\log(p_{\text{正确类别}})
\]

假设正确答案是狗。

如果模型：

```text
P(狗) = 0.9
```

那么：

\[
-\log(0.9)\approx0.105
\]

Loss 很小。

如果：

```text
P(狗)=0.5
```

那么：

\[
-\log(0.5)\approx0.693
\]

更大。

如果：

```text
P(狗)=0.01
```

那么：

\[
-\log(0.01)\approx4.605
\]

巨大。

所以：

```text
正确类别概率

1.0 ─────────────→ Loss 接近 0

0.8 ─────────────→ Loss 较小

0.5 ─────────────→ Loss 变大

0.1 ─────────────→ Loss 很大

0.01 ────────────→ Loss 巨大
```

教授说：

“尤其是——”

> **如果模型非常自信地预测错了，会受到很重的惩罚。**

## 十五、`CrossEntropyLoss` 前面不要自己加 Softmax

PyTorch 中：

```python
loss_fn = nn.CrossEntropyLoss()
```

通常直接这样：

```python
logits = model(x)

loss = loss_fn(logits, target)
```

而不是：

```python
prob = torch.softmax(logits, dim=1)

loss = loss_fn(prob, target)
```

为什么？

因为：

> **`nn.CrossEntropyLoss()` 期望输入的是原始 logits。**

它内部已经把所需的 `LogSoftmax` 和 `NLLLoss` 组合起来了。

可以概念化成：

```text
CrossEntropyLoss

≈

LogSoftmax
+
NLLLoss
```

所以：

```python
loss = nn.CrossEntropyLoss()(
    logits,
    target
)
```

内部已经完成了对应计算。

## 十六、为什么 PyTorch 要这么设计？

林默问：

“直接 Softmax 再 log 不就行了吗？”

教授写：

```text
logits
 ↓
Softmax
 ↓
log
```

数学上能推。

但实际计算机使用有限精度浮点数。

假设某个类别概率极小：

```text
0.000000000000000000000000000001
```

数值计算可能出现精度问题。

因此实际实现通常会通过更稳定的数学形式计算。

所以 PyTorch 让你直接提供：

```text
logits
```

它内部做数值稳定处理。

因此要形成条件反射：

```python
nn.CrossEntropyLoss()
```

配：

```text
raw logits
```

**训练时通常不要在前面手动 Softmax。**

## 十七、那什么时候用 Softmax？


## 十八、`dim=1` 又是什么鬼？

林默盯着：

## 二十二、链式法则

假设：

\[
x\rightarrow a\rightarrow b\rightarrow Loss
\]

其中：

\[
a=f(x)
\]

\[
b=g(a)
\]

\[
L=h(b)
\]

如果要求：

\[
\frac{dL}{dx}
\]

数学上：

\[
\frac{dL}{dx}
=
\frac{dL}{db}
\cdot
\frac{db}{da}
\cdot
\frac{da}{dx}
\]

这就是：

> **Chain Rule——链式法则。**

林默突然意识到：

“所以反向传播不是一种神秘的 AI 算法？”

“不是。”

> **反向传播的数学核心，就是利用链式法则高效地计算梯度。**

而 PyTorch 的 Autograd，则替你记录计算关系，并完成这些梯度计算。

---

## 二十三、昨天那个问题终于彻底回答了

第一章的时候，林默问：

> “反向传播其实就是计算导数吗？”

现在教授给出了更准确的答案：

**可以这么理解，但要再精确一点：**

> **反向传播是在计算图上，从最终 Loss 出发，利用链式法则反向传播梯度，高效计算各个需要梯度的参数对 Loss 的导数。**

也就是：

```text
forward
──────────────────────→

x
↓
Linear
↓
ReLU
↓
Linear
↓
CrossEntropy
↓
Loss


backward
←──────────────────────

Loss
↑
算梯度
↑
算梯度
↑
算梯度
↑
算梯度
↑
Parameter.grad
```

最后，每一个 Parameter 身上都有：

```text
param.grad
```

然后：

```text
optimizer.step()
```

读取这些梯度，修改参数。

```text
         │   链式法则        │
         └──────────────────┘
                  │
                  ▼
         Parameter.grad
                  │
                  │ optimizer.step()
                  ▼
           Parameter 改变
                  │
                  └──────────────┐
                                 │
                                 ▼
                              下一轮
```

林默看了很久。

到这里，他终于能解释 PyTorch 最经典的五行代码：

```python
optimizer.zero_grad()

pred = model(x)

loss = loss_fn(pred, target)

loss.backward()

optimizer.step()
```

不是背 API。

而是：

```text
清掉上轮梯度

→ 用当前参数预测

→ 衡量预测有多差

→ 用链式法则计算每个参数对 Loss 的梯度

→ 根据梯度修改参数
```

这就是最基础的：
