### 一、语言模型的终极任务：预测下一个 Token

教授写下一段文本：

```text
我 喜欢 学习 PyTorch
```

假设经过 Tokenizer 后得到：

```text
[我, 喜欢, 学习, PyTorch]
```

每个 Token 有自己的 ID：

```text
我       → 1
喜欢     → 2
学习     → 3
PyTorch  → 4
```

于是文本变成：

```python
tokens = [1, 2, 3, 4]
```

林默问：

“然后呢？”

教授说：

“如果要让模型学会预测下一个 Token，我们应该怎么构造训练数据？”

他在黑板上画出：

```text
输入：我
目标：喜欢

输入：我 喜欢
目标：学习

输入：我 喜欢 学习
目标：PyTorch
```

林默点头。

“相当于不断向后移动一个位置。”

“对。”

这就是：

Next Token Prediction——下一个 Token 预测。

数学上，我们希望模型学习：

\[ P(x_t\mid x_1,x_2,\ldots,x_{t-1}) \]

意思是：

> 已经知道前面的 Token，预测下一个 Token 出现的概率。

教授继续：

“比如当前输入是：”

```text

```

模型可能输出：

```text
PyTorch   0.70
Java      0.15
Python    0.10
其他      0.05
```

然后根据这些概率选择下一个 Token。

这便是文本生成的起点。

### 四、Causal Mask：禁止偷看未来

假设有四个 Token：

```text
A B C D
```

没有 Mask：

```text
A → A B C D
B → A B C D
C → A B C D
D → A B C D
```

但是 GPT 的因果注意力要求：

```text
A → A
B → A B
C → A B C
D → A B C D
```

Causal Attention Mask



A

B

C

D

A

B

C

D

允许关注

禁止关注未来

教授说：

“对于每个位置，模型只能利用当前及之前的 Token 表示。”

“这样，虽然所有位置的计算可以在训练时并行完成，但每个位置仍然遵守不能看未来的约束。”

他写出代码：

```python
seq_len = 4
mask = torch.triu(torch.ones(seq_len, seq_len, dtype=torch.bool), diagonal=1)
```

在 `nn.MultiheadAttention` 中，可以这样使用：

```python
output, _ = attention(    x, x, x,    attn_mask=mask,    need_weights=False)
```

这里的 `True` 表示禁止关注该位置。

“注意，”教授补充，“PyTorch 不同 Attention API 对布尔 Mask 的约定不完全相同，用时要看具体接口。”

### 七、训练 GPT 时，Loss 怎么算？

林默很快想起第四章。

“CrossEntropyLoss？”

“没错。”

模型输出：

```text
logits:

[B, N, V]
```

标签：

```text
targets:

[B, N]
```

其中：

```text
B = Batch Size
N = Sequence Length
V = Vocabulary Size
```

但普通的：

```text
nn.CrossEntropyLoss()
```

对于二维分类 logits，通常期望：

```text
[样本数量, 类别数量]
```

于是我们可以把：

```text
[B, N, V]
```

变成：

```text
[B × N, V]
```

标签：

```text
[B, N]
```

变成：

```text
[B × N]
```

代码：

```python
loss = F.cross_entropy(    logits.reshape(-1, vocab_size),    targets.reshape(-1))
```

编写批次生成函数：

```python
def get_batch():

    x = torch.stack([data[i:i + block_size] for i in starts])
    y = torch.stack([data[i + 1:i + block_size + 1] for i in starts])
    return x, y
```

#### 4. 构建 Transformer Block

我们继续使用上一章的 Pre-Norm 结构，但加入因果 Mask。

```python
class TransformerBlock(nn.Module):
    def __init__(self, d_model, num_heads):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.attn = nn.MultiheadAttention(d_model, num_heads, batch_first=True)
        self.ln2 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, 4 * d_model), nn.GELU(),
            nn.Linear(4 * d_model, d_model),
        )

    def forward(self, x):
        T = x.size(1)
        causal_mask = torch.triu(
            torch.ones(T, T, device=x.device, dtype=torch.bool), diagonal=1
        )
        h = self.ln1(x)
        out, _ = self.attn(h, h, h, attn_mask=causal_mask, need_weights=False)
        x = x + out
        return x + self.ffn(self.ln2(x))
```

教授指着：

```python
T = x.size(1)
```

“这里就是序列长度。”

“为什么每次都根据 x 取？”

林默回答：

“因为训练和生成时，输入序列长度可能不同。”

“对。”

#### 5. 构建 Mini-GPT

终于到了核心代码。

```python
class MiniGPT(nn.Module):
    def __init__(self, vocab_size, d_model=64, num_heads=4,
                 num_layers=2, block_size=32):
        super().__init__()
        self.block_size = block_size
        self.token_embedding = nn.Embedding(vocab_size, d_model)
        self.position_embedding = nn.Embedding(block_size, d_model)
        self.blocks = nn.Sequential(*[
            TransformerBlock(d_model, num_heads) for _ in range(num_layers)
        ])
        self.ln_f = nn.LayerNorm(d_model)
        self.lm_head = nn.Linear(d_model, vocab_size)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        if not 0 < T <= self.block_size:
            raise ValueError('Sequence length must be in [1, block_size]')
        positions = torch.arange(T, device=idx.device)
        x = self.token_embedding(idx) + self.position_embedding(positions)
        logits = self.lm_head(self.ln_f(self.blocks(x)))
        loss = None
        if targets is not None:
            # targets are ALREADY shifted by get_batch; do not shift twice.
            loss = F.cross_entropy(logits.reshape(-1, logits.size(-1)), targets.reshape(-1))
        return logits, loss
```

林默沉默了。

这是他第一次真正看到：

> 一个从 Token ID 开始，一直到整个词表预测结果的完整语言模型。

教授问：

“这段代码，有没有看不懂的？”

林默指着：

```python
self.blocks = nn.Sequential(*[TransformerBlock(d_model, num_heads) for _ in range(num_layers)])
```

“这里的 `*` 是什么？”

教授解释：

“Python 的参数解包语法。”

例如：

```python
layers = [    TransformerBlock(64, 4),    TransformerBlock(64, 4)]
```

使用：

```text
nn.Sequential(*layers)
```

等价于把这些层依次传给 `nn.Sequential`。

所以我们就能轻松控制：

```python

num_layers = 6

num_layers = 12
```

### 十三、怎么从 Logits 选择一个 Token？

教授给出：

```text
模型预测：

实验室  3.2
教室    2.8
医院    1.1
广场    0.7
```

林默说：

“直接取最大值？”

```python
next_token = last_logits.argmax(dim=-1)
```

教授点头。

“这叫 Greedy Decoding。”

即：

> 每次选择当前概率最高的 Token。

但问题来了。

“如果每次都选最大值，会怎样？”

林默想了想。

“生成结果会比较固定？”

“对。”

而且贪心策略并不保证生成整段文本的联合概率最高。

它只是在每一个局部步骤做最大值选择。

所以现代语言模型经常使用：

> Sampling——采样。

### 十四、Sampling：按概率抽取下一个 Token

假设 Softmax 后：

```text

教室    0.25
医院    0.10

```

不是直接选择：

```text

```

而是按这些概率随机抽取。

因此：

```text

第二次生成：
实验室

第三次生成：
教室
```

不同运行可能得到不同结果。

代码：


### 十五、Temperature：控制生成有多随机

教授又写：

```python
temperature = 1.0
```

然后：

```python
logits = logits / temperature
```

林默想起 Attention 中的缩放。

“又是除法？”

教授点头。

“但这次目的不同。”

Temperature 控制的是：

> 采样概率分布的尖锐程度。

公式：

\[ P_i= \frac{e^{z_i/T}} {\sum_j e^{z_j/T}} \]

其中：

\[ T>0 \]

温度越低：

```text
概率越集中于高 logit 的 Token
```

温度越高：

```text
概率分布越平缓
```

假设 logits：

```text
[3, 2, 1]
```

Temperature 采样实验

T = 1.0

低随机性

1.0

高随机性

实验室

66.5%

教室

24.5%

医院

9.0%

拖动温度，观察相同 logits 如何产生不同的采样概率。T 趋近 0 时越来越接近贪心选择。

林默发现：

“所以 Temperature 不改变模型参数。”

“只是改变生成时的概率分布？”

教授点头。

“它是推理解码策略的一部分。”

### 十六、Top-k：只允许最有希望的 k 个候选参与

教授继续：

“你真的希望每次生成时，所有 Token 都有机会被采样吗？”

林默摇头。

“那些概率极小的 Token，可能生成奇怪文本。”

“所以可以使用 Top-k。”

例如：

```text

```

原始概率：

```text

B  0.25
C  0.15
D  0.06
E  0.04
```

只保留：

```text
A
B
C
```

其他候选：

```text

```

直接排除。

然后对保留下来的概率重新归一化。

PyTorch：

```python
values, _ = torch.topk(logits, k=min(3, logits.size(-1)))
threshold = values[:, [-1]]
logits = logits.masked_fill(logits < threshold, float("-inf"))
```

之后 Softmax，低于阈值的 Token 就不会被采样。

### 十七、Top-p：候选数量不固定

林默问：

“Top-k 只保留固定数量，是不是有点死板？”

教授点头。

于是出现：

**Top-p / Nucleus Sampling**

它不固定候选 Token 数量。

而是选择概率最高的一组 Token，使累计概率达到设定阈值。

例如：

```python
top_p = 0.9
```

概率排序：

```text
A  0.50  累计 0.50
B  0.25  累计 0.75
C  0.15  累计 0.90
D  0.06  累计 0.96
E  0.04  累计 1.00
```

那么可以保留：

```text
A、B、C
```

因为累计概率已经达到：

```text
0.90
```

教授说：

“当模型很确定时，可能只需要几个候选。”

“当模型不确定时，可能需要更多候选。”

这就是 Top-p 相比固定 Top-k 的一个特点。

### 十八、完成文本生成函数

教授说：

“我们先实现一个最简单的采样版本，不使用 Top-k 和 Top-p。”

```python
@torch.no_grad()
def generate(model, idx, max_new_tokens, temperature=1.0, top_k=None, top_p=1.0):
    if temperature <= 0 or not 0 < top_p <= 1:
        raise ValueError('Require temperature > 0 and 0 < top_p <= 1')
    if top_k is not None and top_k < 1:
        raise ValueError('top_k must be positive')
    was_training = model.training
    model.eval()
    try:
        for _ in range(max_new_tokens):
            idx_cond = idx[:, -model.block_size:]
            logits, _ = model(idx_cond)
            logits = logits[:, -1, :] / temperature
            if top_k is not None:
                threshold = logits.topk(min(top_k, logits.size(-1))).values[:, [-1]]
                logits = logits.masked_fill(logits < threshold, float('-inf'))
            if top_p < 1:
                sorted_logits, order = logits.sort(descending=True, dim=-1)
                cumulative = sorted_logits.softmax(dim=-1).cumsum(dim=-1)
                remove = cumulative > top_p
                # Keep the first token crossing the threshold, including top-1.
                remove[:, 1:] = remove[:, :-1].clone()
                remove[:, 0] = False
                sorted_logits = sorted_logits.masked_fill(remove, float('-inf'))
                logits = torch.empty_like(logits).scatter(1, order, sorted_logits)
            next_token = torch.multinomial(logits.softmax(dim=-1), num_samples=1)
            idx = torch.cat([idx, next_token], dim=1)
    finally:
        model.train(was_training)
    return idx
```

### 二十二、KV Cache：把过去的计算结果保存起来

教授回顾上一章：

\[ Q=XW_Q \]

\[ K=XW_K \]

\[ V=XW_V \]

在自回归推理中，新 Token 需要关注之前的 Token。

对于此前已经计算过的 Token，它们在某一层的 Key 和 Value 可以缓存起来。

例如：

```text
已经生成：

A B C
```

保存：

```text
K_A
K_B
K_C

V_A
V_B
V_C
```

下一步生成 D：

```text
只需要计算新 Token 的相关投影
```

然后把新的 K、V 加入缓存。

```text
KV Cache

┌──────────────────────────┐
│ K_A  K_B  K_C  K_D      │
│ V_A  V_B  V_C  V_D      │
└──────────────────────────┘
```

后续新 Query 就可以关注这些历史 K/V。

林默突然意识到：

“所以不用每次重新计算历史 Token 的所有 Attention 投影。”

“对。”

不过教授强调：

“KV Cache 不是把所有计算成本都消灭了。”

“新 Token 仍然需要和已有 Key 计算 Attention，而且缓存本身占用显存。”

“随着上下文长度增加，KV Cache 也会增长。”

### 二十三、Prefill 与 Decode

教授在黑板上写两个阶段。

```text

```

林默问：

“这又是什么？”

教授回答：

“这是现代 LLM 推理工程里非常重要的两个阶段。”

**Prefill 阶段**

用户输入：

```text

```

假设 Tokenizer 生成：

```text
100 个 Token
```

模型需要处理这 100 个 Token，建立它们的上下文表示和各层 KV Cache。

这一阶段：

```text

     ↓
批量处理 Prompt Token
     ↓
建立 KV Cache
     ↓
预测第一个新 Token
```

通常称为：

Prefill。

**Decode 阶段**

开始生成：

```text

第 2 个 Token
第 3 个 Token
...
```

借助 KV Cache，通常只需要处理新加入的 Token，而不用把整个前缀从头经过每一层。

这一阶段叫：

### 二十四、为什么 Prefill 和 Decode 的性能瓶颈不同？

教授继续。

“Prefill 处理较长的输入序列，通常有较大的矩阵计算量。”

“Decode 每一步只增加少量 Token，却需要读取大量模型权重和 KV Cache。”

因此在实际硬件与批处理配置下，经常出现：

```text
Prefill
→ 更容易利用大规模并行计算
→ 计算吞吐是重要因素

Decode
→ 单步计算规模较小
→ 内存带宽和访存成本常常成为重要瓶颈
```

不过这不是绝对定律，模型规模、Batch Size、序列长度、硬件和实现方式都会影响瓶颈。

林默点头。

“所以模型推理优化，并不只是换一张更强的显卡。”

教授说：

“还涉及 KV Cache、量化、批处理、Attention Kernel、并行策略。”
