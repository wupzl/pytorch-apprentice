## 一、第一场灾难：梯度在深层网络中消失

教授没有立即讨论 Transformer。

而是重新写下第一章的公式：

\[ y=wx \]

然后：

\[ L=(y-target)^2 \]

“你还记得 `backward()` 的本质吗？”

林默回答：

“链式法则。”

“很好。”

教授写下：

\[ x\rightarrow f_1\rightarrow f_2\rightarrow f_3\rightarrow L \]

如果求：

\[ \frac{\partial L}{\partial x} \]

需要：

\[ \frac{\partial L}{\partial x} = \frac{\partial L}{\partial f_3} \cdot \frac{\partial f_3}{\partial f_2} \cdot \frac{\partial f_2}{\partial f_1} \cdot \frac{\partial f_1}{\partial x} \]

林默点头。

“这不是之前讲过的吗？”

教授说：

“假设每一层的局部导数都是 0.5。”

那么经过一层：

\[ 0.5 \]

经过两层：

\[ 0.5^2=0.25 \]

经过十层：

\[ 0.5^{10}\approx0.000977 \]

经过一百层：

\[ 0.5^{100}\approx7.89\times10^{-31} \]

林默愣住。

“一百层之后，几乎是零？”

“对。”

这是一个简化的标量例子。真实神经网络的梯度涉及矩阵、激活函数和复杂的计算路径，不是简单把每层梯度相乘成一个数字，但它能说明问题。

如果反向传播中的许多局部变换持续压缩梯度，就可能出现：

> Vanishing Gradient——梯度消失。

反过来，如果连续放大，也可能出现：

> Exploding Gradient——梯度爆炸。

于是林默终于意识到：

“我堆的 96 层 Attention，可能根本没有顺利学起来。”

教授点头。

“这正是残差连接想解决的重要问题之一。”

## 二、残差连接：给梯度修一条高速公路

教授在黑板上画：

```text

       │
       ▼
   Attention
       │
```

然后画出另一种结构：

```text
x ──────────────┐
       │               │

   Attention           │
       │               │

       + ◄─────────────┘
       │

```

林默指着旁边那条线。

“这是什么？”

“捷径。”

“什么意思？”

教授写下：

普通网络：

\[ y=F(x) \]

残差网络：

\[ \boxed{y=x+F(x)} \]

林默看着公式。

“就多加了一个 x？”

“对。”

“这也太简单了吧？”

教授笑了。

“恰恰是这一个加法，改变了深度神经网络的训练方式。”

## 三、为什么 `x + F(x)` 有用？

教授写：

\[ y=x+F(x) \]

现在对 \(x\) 求导：

\[ \frac{\partial y}{\partial x} = I+\frac{\partial F(x)}{\partial x} \]

这里的 \(I\) 是恒等映射对应的单位矩阵。

如果暂时只考虑一维情况：

\[ \frac{dy}{dx} = 1+F'(x) \]

林默突然坐直。

“等等。”

“以前梯度只能经过 F。”

“现在多了一条导数为 1 的路径！”

教授点头。

```text
普通网络反向传播：

Loss
  │
  ▼
F 的梯度
  │
  ▼
前一层


残差网络反向传播：

       Loss
         │
         ▼
       加法
       /  \
      /    \
     ▼      ▼
   F路径   恒等路径
     \      /
      \    /
       ▼
      前一层
```

恒等路径为梯度传播提供了一条额外通道。

不过教授马上补充：

“不能因此认为残差网络绝对不会出现梯度消失或爆炸。不同路径的梯度仍可能相互抵消或放大。”

“残差连接的价值在于，它通常能明显改善深层网络的优化难度。”

## 四、残差连接的第二个秘密：学习变化，而不是从头重建

教授换了一个角度。

“假设一个 Token 已经拥有不错的表示。”

例如：

```text
x = “苹果手机”的上下文表示
```

经过某个 Attention 层后，模型只是希望：

```text
增加一点“没电”的语义信息
```

普通网络：

\[ y=F(x) \]

意味着 F 必须产生完整的新表示。

但残差网络：

\[ y=x+F(x) \]

可以让：

```text
x
│
├── 保留原来的信息
│
└── F(x) 负责补充或修正信息
```

例如：

```text
x：

已经知道这是“手机”


F(x)：

补充“没电”相关信息


x + F(x)：

得到更丰富的手机表示
```

这只是帮助理解的类比，真实表示并不是逐项标注语义。

但设计思想非常重要：

> 模型不一定需要每层都重新生成全部信息，它可以在已有表示的基础上学习增量修正。

## 五、PyTorch 里的残差连接

教授打开编辑器：

```python
import torch
import torch.nn as nn

class ResidualBlock(nn.Module):
    def __init__(self, dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(dim, dim), nn.ReLU(), nn.Linear(dim, dim)
        )

    def forward(self, x):
        return x + self.net(x)
```

林默看着：

```python
return x + self.net(x)
```

“就这一句？”

“核心就是这一句。”

假设输入：

```python
x = torch.randn(32, 128)
```

形状：

```text
[32, 128]
```

那么：

```python
self.net(x)
```

也必须输出：

```text
[32, 128]
```

才能相加。

教授提醒：

> 最普通的恒等残差连接要求两条路径的输出形状兼容。

如果：

```text
x:
[32, 128]

F(x):
[32, 256]
```

就不能直接进行这种残差相加。

某些网络会使用投影层调整维度，但 Transformer Block 通常让外部隐藏维度保持不变。

## 七、LayerNorm：让每个 Token 整理自己的数值

教授写：

```python
nn.LayerNorm(512)
```

林默问：

“又一个新层？”

“对。”

“但是理解它之前，我们先做一个很简单的数学计算。”

假设一个 Token 的隐藏向量：

\[ x=[1,2,3] \]

计算平均值：

\[ \mu=\frac{1+2+3}{3}=2 \]

然后计算方差：

\[ \sigma^2 = \frac{(1-2)^2+(2-2)^2+(3-2)^2}{3} = \frac23 \]

标准化：

\[ \hat{x}_i= \frac{x_i-\mu}{\sqrt{\sigma^2+\epsilon}} \]

忽略很小的 \(\epsilon\)，得到近似：

\[ \hat{x}=[-1.225,0,1.225] \]

林默看着结果。

“平均值变成零了。”

“对。”

“方差也变成接近一。”

“对。”

## 八、LayerNorm 不是简单把数值固定住

林默发现两个新变量：

```text

```

教授解释：

“标准化之后，模型还可以通过可学习参数调整每个特征维度的缩放和平移。”

所以 LayerNorm 内部通常也有：

```text

bias → beta
```

在 PyTorch 里：


可以看到：

“没错。”

```text

```

```text

```

还可能包含：

```text

```

优化器统一管理这些参数。

## 九、LayerNorm 究竟沿哪个维度计算？

教授写出 Transformer 中最经典的 Tensor 形状：

```text
X.shape = [B, N, D]
```

例如：

```text
[32, 128, 512]
```

代表：

```text
32   → Batch Size
128  → Sequence Length
512  → Hidden Dimension
```

然后：

```python
ln = nn.LayerNorm(512)
y = ln(x)
```

问题来了。

“它对哪一维计算均值和方差？”

林默思考片刻。

“512？”

“对。”

LayerNorm 的归一化范围

示意图：每个 Token 独立地沿隐藏特征维度计算统计量，不是把整个 Batch 混在一起。

教授说：

“对于这种输入，`LayerNorm(512)` 会分别处理每个样本、每个 Token 的 512 维向量。”

也就是：

```text
Batch 1
  Token 1 → 对512维归一化
  Token 2 → 对512维归一化
  ...

Batch 2
  Token 1 → 对512维归一化
  Token 2 → 对512维归一化
  ...
```

不会把所有 Token 和 Batch 的数值混在一起求同一组均值、方差。

## 十、为什么 Transformer 常用 LayerNorm，而不是 BatchNorm？

林默突然想起第六章。

“教授，BatchNorm 不也能归一化吗？”

“当然。”

“那为什么 Transformer 里常见 LayerNorm？”

教授画出两个概念。

| 对比          | BatchNorm          | LayerNorm         |
| ----------- | ------------------ | ----------------- |
| 典型归一化范围     | 跨 Batch 等维度，对各通道统计 | 对每个样本的指定特征维度统计    |
| 是否受同批其他样本影响 | 训练时通常会             | 通常不会              |
| 训练与推理统计方式   | 常见实现存在差异           | 通常一致              |
| 常见使用场景      | CNN 等              | Transformer、LLM 等 |

教授说：

“语言模型的输入长度、批次组成可能不断变化。”

“尤其在自回归生成时，每次可能只处理一个新 Token。”

“LayerNorm 不依赖跨样本统计，因此非常适合这种场景。”

不过他又补充：

“现代大语言模型也大量使用 RMSNorm 等变体，不能简单认为所有 Transformer 都一定使用 LayerNorm。”

林默在笔记上写下：

> BatchNorm 更多考虑批次等维度上的统计，LayerNorm 通常独立处理每个 Token 的特征向量。


“Attention 干什么？”

林默回答：

“让 Token 根据 Q、K、V 从其他 Token 聚合信息。”

“很好。”

“那它是否已经足够？”

林默犹豫了。

“好像还缺非线性处理？”

教授点头。

“这就是今天第三个核心模块。”

### FFN

全称：

Feed-Forward Network

在 Transformer 中通常也称：

Position-wise Feed-Forward Network。

## 十二、FFN：每个 Token 自己的加工车间

教授画了两座工厂。

第一座：

```text
Self-Attention

Token A ───┐
Token B ───┼──► 信息交换
Token C ───┼──► 上下文融合
Token D ───┘
```

第二座：

```text
FFN

Token A → 自己加工

Token B → 自己加工

Token C → 自己加工

Token D → 自己加工
```

林默问：

“什么意思？”

教授解释：

“Self-Attention 的一个重要作用，是在不同 Token 之间交换信息。”

“FFN 则通常对每个 Token 的隐藏向量，独立应用同一套非线性变换。”

也就是说：

> Attention 负责跨 Token 的信息交互，FFN 负责对每个 Token 的特征进行非线性加工。

这是一种非常实用的理解方式，并非两者功能的绝对边界。

## 十三、FFN 为什么要先升维，再降维？

教授写下：

```python
nn.Linear(512, 2048)
```

再写：

```python
nn.Linear(2048, 512)
```

林默看着数字。

“512 变 2048，再变回 512？”

“对。”

经典 FFN 的结构：

```text
输入

512维
  │
  ▼
Linear(512, 2048)
  │
  ▼
2048维
  │
  ▼
激活函数
  │
  ▼
Linear(2048, 512)
  │
  ▼
512维
```

对应公式：

\[ FFN(x)=W_2\phi(W_1x+b_1)+b_2 \]

其中：

\[ \phi \]

代表激活函数。

教授问：

“为什么不是从头到尾都保持 512 维？”

林默思考。

“因为扩展中间维度，可以提供更丰富的中间特征表达？”

“对。”

更大的中间维度给非线性变换提供了更多表达容量。

但教授强调：

> 升维并不自动保证模型更好，它也会增加参数量和计算量。

## 十四、FFN 的参数量究竟有多大？

教授写：

```python
fc1 = nn.Linear(512, 2048)
fc2 = nn.Linear(2048, 512)
```

先算第一层。

Weight：

\[ 512\times2048=1,048,576 \]

Bias：

\[ 2048 \]

第一层总计：

\[ 1,050,624 \]

第二层：

Weight：

\[ 2048\times512=1,048,576 \]

Bias：

\[ 512 \]

第二层总计：

\[ 1,049,088 \]

整个 FFN：

\[ \boxed{2,099,712\text{ 个参数}} \]

林默愣住。

“一个小小的 FFN 就两百多万参数？”

教授点头。

“所以千万不要觉得 Transformer 里的参数主要都在 Attention。”

“在许多常见架构中，FFN/MLP 占据了相当大比例的参数。”

## 十五、为什么激活函数变成 GELU？

林默想起第三章：

```python
nn.ReLU()
```

于是问：

“这里直接用 ReLU 不就可以了吗？”

教授回答：

“当然可以。早期 Transformer 也使用过 ReLU。”

“但是后来出现了许多更常用的选择。”

例如：

```python
nn.GELU()
```

GELU：

Gaussian Error Linear Unit

公式：

\[ GELU(x)=x\Phi(x) \]

其中：

\[ \Phi(x) \]

是标准正态分布的累积分布函数。

林默看着公式。

“这又是什么意思？”

教授画出 ReLU 和 GELU 的曲线。

ReLU

负数直接截断为零，零点处有折角

GELU

平滑过渡，部分负输入也有非零输出

教授解释：

ReLU：

\[ ReLU(x)=\max(0,x) \]

对于负数：

```text
全部输出 0
```

而 GELU 不会简单地把所有负数直接截断到零。

例如：

```text
输入 -1

ReLU(-1) = 0

GELU(-1) ≈ -0.159
```

林默点头。

“所以 GELU 的变化更加平滑。”

“对。”

“但不要记成 GELU 永远比 ReLU 更好。不同任务、模型架构和硬件实现会影响最终选择。”

## 十六、SiLU 与 SwiGLU：大模型时代的新车间

教授又写出两个名字：

```text
SiLU

SwiGLU
```

SiLU：

\[ SiLU(x)=x\sigma(x) \]

其中：

\[ \sigma(x) \]

是 Sigmoid。

PyTorch：

```python
activation = nn.SiLU()
```

而 SwiGLU 则更特别。

它不是简单地把：

```text
Linear
↓
ReLU
↓
Linear
```

换掉一个激活函数。

它引入了门控结构。

一种常见形式：

\[ SwiGLU(x)= \left( SiLU(xW_g)\odot(xW_u) \right)W_d \]

忽略偏置。

其中：

\[ \odot \]

表示逐元素相乘。

教授画：

```text
x
                 / \
                /   \
               ▼     ▼
             Linear Linear
               │      │
               ▼      │
              SiLU    │
               │      │
               └──┬───┘
                  │
                  ▼
                逐元素乘
                  │
                  ▼
                Linear
                  │
                  ▼
                 输出
```

林默突然发现：

“这里有两条路径。”

“一条经过 SiLU，另一条保留另一种投影。”

“然后两个结果相乘？”

“对。”

教授说：

“你可以把它理解为一种可学习的门控机制，让不同特征之间产生更灵活的交互。”

现代不少 LLM 使用类似 SwiGLU 的 FFN 变体。

注意，不同模型的隐藏维度设置可能不同，并不一定继续沿用经典 FFN 的四倍扩展比例。

## 十八、Pre-Norm Transformer Block

教授首先画出一种常见的现代结构：

Pre-Norm Transformer Block

林默盯着这张图。

“先 LayerNorm。”

“然后 Attention。”

“再和最初的 x 相加。”

“接着又 LayerNorm。”

“再 FFN。”

“最后再加一次残差？”

教授点头。

数学上：

\[ h=x+Attention(LN(x)) \]

然后：

\[ \boxed{y=h+FFN(LN(h))} \]

这就是一种标准的 Pre-Norm Block 写法。

## 十九、为什么叫 Pre-Norm？

教授问：

“Norm 在哪里？”

林默回答：

“Attention 和 FFN 前面。”

“所以叫 Pre-Norm。”

对应的另一种结构：

Post-Norm：

\[ h=LN(x+Attention(x)) \]

\[ y=LN(h+FFN(h)) \]

两种设计的区别：

|              | Pre-Norm    | Post-Norm            |
| ------------ | ----------- | -------------------- |
| LayerNorm 位置 | 子层前         | 残差相加后                |
| 残差主路径        | 更直接         | 经过后置归一化              |
| 深层优化         | 通常更容易稳定训练   | 可能更依赖初始化和训练配置        |
| 使用情况         | 现代 LLM 中很常见 | 原始 Transformer 等架构使用 |

教授补充：

“原始的 Transformer 采用的是 Post-Norm 结构。后来许多深层语言模型采用 Pre-Norm 或其变体。”

“不要把 Pre-Norm 理解成所有指标上都绝对更好，它主要是一个重要的优化与架构权衡。”

## 二十、用 PyTorch 亲手造一个 Transformer Block

林默已经迫不及待。

“教授，我们自己实现吧。”

教授打开编辑器。

“这次我们不只画结构。”

“我们真正写一个能执行的 Transformer Block。”

先做一个简化实现，使用 PyTorch 已有的多头 Attention。

```python
"""Minimal Pre-Norm block; python examples/transformer.py."""
import torch
from torch import nn


class TransformerBlock(nn.Module):
    def __init__(self, d_model=128, num_heads=4):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.attn = nn.MultiheadAttention(d_model, num_heads, batch_first=True)
        self.ln2 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, 4 * d_model),
            nn.GELU(),
            nn.Linear(4 * d_model, d_model),
        )

    def forward(self, x, causal=False, padding_mask=None):
        h = self.ln1(x)
        mask = None
        if causal:
            n = x.size(1)
            mask = torch.triu(torch.ones(n, n, device=x.device, dtype=torch.bool), diagonal=1)
        out, _ = self.attn(h, h, h, attn_mask=mask,
                           key_padding_mask=padding_mask, need_weights=False)
        x = x + out
        return x + self.ffn(self.ln2(x))
```

林默看完，几乎立刻指出：

```python
attn_out, _ = self.attn(h, h, h)
```

“为什么输入三个 h？”

教授回答：

“因为这是 Self-Attention。”

对应：

```text
Query 来源：h

Key 来源：h

Value 来源：h
```

注意，这不是说 Q、K、V 三个投影后的向量完全相同。

`nn.MultiheadAttention` 内部依然会执行各自的可学习投影。

## 二十一、为什么 `batch_first=True`？

教授又指向：

```python
batch_first=True
```

之前我们一直使用：

```text
[B, N, D]
```

例如：

```text
[32, 128, 512]
```

但 PyTorch 的 `nn.MultiheadAttention` 在 `batch_first=False` 时，三维输入通常使用：

```text
[N, B, D]
```

设置：

```python
batch_first=True
```

后，输入就可以使用：

```text
[batch_size, seq_len, hidden_dim]
```

也就是：

```text
[B, N, D]
```

这与我们前面学习的 Tensor 形状保持一致。

## 二十二、第一次运行 Transformer Block

教授写：

```python
block = TransformerBlock(d_model=128, num_heads=4)
x = torch.randn(2, 10, 128)
y = block(x)
print(y.shape)
```

输出：

```python
torch.Size([2, 10, 128])
```

林默问：

“为什么维度没变？”

教授指向两次残差连接。

“因为这个 Block 的输入和输出，都需要保持相同的模型隐藏维度。”

具体：

```text
输入：

[B, N, D]
[2, 10, 128]

       ↓

LayerNorm

[2, 10, 128]

       ↓

Multi-Head Attention

[2, 10, 128]

       ↓

Residual Add

[2, 10, 128]

       ↓

FFN

[2, 10, 512]
       ↓
[2, 10, 128]

       ↓

Residual Add

[2, 10, 128]
```

所以每个 Block 都能保持：

\[ [B,N,D] \]

不变。

这正是它能够被反复堆叠的重要原因。

## 二十三、但是这个 Block 还不能直接当 GPT

林默突然说：

“那我只要把它堆 96 层，不就做出了 GPT？”

教授摇头。

“还差一个极其关键的约束。”

“上一章我们刚讲过。”

林默很快反应过来。

“Causal Mask！”

“没错。”

刚才我们写：

```python
attn_out, _ = self.attn(
    h, h, h,
    need_weights=False,
)
```

没有传入因果 Mask。

因此：

> 这个实现默认允许每个 Token 关注序列中其他所有 Token。

它更接近一个不带 Padding Mask 的双向 Self-Attention 模块，而不是完整的 GPT 自回归注意力层。

如果想做 GPT，需要限制：

```text
Token 1 不能看到 2、3、4……

Token 2 不能看到 3、4……

Token 3 不能看到 4……
```

可以构造：

```python
seq_len = x.size(1)
causal_mask = torch.triu(
    torch.ones(seq_len, seq_len, device=x.device, dtype=torch.bool),
    diagonal=1,
)
```

然后：

```python
attn_out, _ = self.attn(
    h, h, h,
    attn_mask=causal_mask,
    need_weights=False,
)
```

这里布尔 `attn_mask=True` 的位置，在 `nn.MultiheadAttention` 中表示禁止关注。

教授提醒：

“不同 Attention API 的布尔 Mask 约定可能不同。以后使用 `scaled_dot_product_attention` 时，不能想当然地照搬这个规则。”

## 二十四、现在真正理解一层 Transformer 在做什么

教授指着输入句子：

> 我把苹果手机放在桌子上，因为它没电了。

经过 Tokenizer：

```text
[我, 把, 苹果手机, 放在, 桌子, 上, ...]
```

Embedding：

```text
[B, N, D]
```

进入一个 Transformer Block。

第一步：

```text
LayerNorm
```

对输入特征做归一化。

第二步：

```text
Self-Attention
```

Token 之间交换上下文信息。

例如“它”可能融合与“苹果手机”“没电”有关的信息。

第三步：

```text
Residual
```

把原有表示与 Attention 输出相加。

第四步：

```text
LayerNorm
```

对更新后的表示再次归一化。

第五步：

```text
FFN
```

每个 Token 独立经过非线性特征变换。

第六步：

```text
Residual
```

保留主路径并叠加本层的 FFN 输出。

于是：

> 一个 Transformer Block 完成了一轮信息交互和特征加工。

而接下来：

```text
Block 1
   ↓
Block 2
   ↓
Block 3
   ↓
...
   ↓
Block 96
```

模型就能够不断构建更复杂的上下文表示。

## 二十五、为什么 Transformer 可以并行处理 Token？

林默想起之前学过的 RNN。

“教授，以前 RNN 不是要一个 Token 一个 Token 处理吗？”

教授点头。

“经典 RNN 的隐藏状态依赖前一个时间步，因此序列维度上的计算有较强的顺序依赖。”

```text
RNN：

Token 1
  ↓
Hidden 1
  ↓
Token 2
  ↓
Hidden 2
  ↓
Token 3
  ↓
...
```

而 Transformer 在训练时可以让一整个序列共同进入 Attention：

```text
Token 1 ─┐
Token 2 ─┤
Token 3 ─┼──► 矩阵运算
Token 4 ─┤
Token 5 ─┘
```

即使使用 Causal Mask，训练期间也可以并行计算多个位置的预测。

林默问：

“那为什么 GPT 推理还是一个 Token 一个 Token 生成？”

教授回答：

“因为生成时，下一个 Token 还没有出现。”

“当前 Token 需要根据之前已经生成的内容进行预测。”

这就涉及：

> Autoregressive Generation——自回归生成。

不过这是下一阶段的内容。

## 二十六、Transformer Block 里的参数到底有多少？

教授突然问：

“我们现在使用：”

```text
d_model = 512

num_heads = 8

FFN hidden = 2048
```

“那么一个 Block 大约有多少参数？”

林默开始计算。

Attention 中，经典多头注意力通常存在：

```text
W_Q

W_K

W_V

W_O
```

每个主要投影矩阵的大小：

\[ 512\times512 \]

四个：

\[ 4\times512^2=1,048,576 \]

FFN：

\[ 512\times2048+2048\times512 \]

等于：

\[ 2,097,152 \]

两个 LayerNorm：

```text
gamma + beta
```

总计：

\[ 2\times(512+512)=2048 \]

如果加上四个 Attention 线性投影和两个 FFN 线性层的偏置：

\[ 2048+2560=4608 \]

那么一个这种具体配置的 Block，总计：

\[ 1,048,576 + 2,097,152 + 2048 + 4608 \]

\[ \boxed{3,152,384\text{ 个参数}} \]

林默愣住。

“一个 Block 就三百多万？”

“对。”

如果有 96 层：

\[ 3,152,384\times96 \]

大约：

\[ 3.03\text{亿} \]

这还没有加：

```text
Token Embedding

位置相关参数（如果有）

最终输出层

其他可能的模块
```

教授说：

“而且更大的模型会把 `d_model` 扩展得更宽，参数量增长会非常快。”

## 二十七、为什么大模型越宽，参数增加得越快？

教授在黑板上写：

\[ D=d_{model} \]

如果 FFN 扩展比例固定为 4：

Attention 主要权重：

\[ 4D^2 \]

FFN 主要权重：

\[ 8D^2 \]

合起来：

\[ 12D^2 \]

忽略偏置和归一化参数：

\[ \boxed{BlockParams\approx12D^2} \]

林默马上发现：

“所以如果 hidden_dim 翻倍——”

\[ (2D)^2=4D^2 \]

“单层主要参数量大约变成四倍！”

教授点头。

“这就是宽度扩展非常昂贵的原因之一。”

而层数翻倍，在其他配置不变时，Block 总参数量则大致翻倍。

因此模型规模可以通过：

```text
增加深度

增加宽度

改变 FFN 扩展比例

改变 Attention 结构

改变词表规模

引入 MoE
```

等方式调整。

## 二十八、为什么现代模型不一定使用普通 Multi-Head Attention？

教授又在黑板上写下：

```text
MHA

MQA

GQA
```

林默疑惑。

“刚理解多头，怎么又变了？”

教授说：

“因为我们刚实现的是一种经典形式。”

“但实际 LLM 工程需要考虑显存和推理速度。”

传统 MHA：

```text
每个 Query Head
有对应的 Key Head 和 Value Head
```

MQA：

```text
多个 Query Head
共享一组 K/V Head
```

GQA：

```text
若干 Query Head
共享一组 K/V Head
```

主要目标之一：

> 减少自回归推理中 KV Cache 的内存占用和访存成本。

“也就是说，有时候模型快不快，不仅仅取决于计算量？”

“对。”

“你已经开始从训练算法走向大模型系统工程了。”

## 二十九、一个隐藏的问题：深层 Transformer 是不是越多层越好？

林默看着自己最初的 96 层模型。

“那我现在有了 LayerNorm、残差和 FFN，是不是层数越多越好？”

教授摇头。

“不是。”

深度增加通常意味着：

```text
更多参数

更多计算

更高训练成本

更长前向和反向传播路径

可能更高的推理延迟
```

但收益不一定线性增加。

真实训练还受到：

```text
训练数据量

数据质量

优化器

学习率

初始化

Batch Size

模型宽度

训练 Token 数

计算预算
```

等因素影响。

甚至可能出现：

> 模型更大，但训练不足，最终效果反而不如配置合理的小模型。

所以现代模型设计不仅要考虑：

```text
能不能训练
```

还要考虑：

```text
能否在有限资源下有效训练

能否在目标硬件上高效推理
```
