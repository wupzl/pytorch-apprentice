## 一、首先认识 Sample

假设我们做一个非常简单的任务：

```text

```

可以写成：


这就是一个：

> **Sample——样本**

所以：

```text

```

如果有 10000 个学生：

```text

Sample 2
Sample 3
...

```

这些样本集合起来，就是：

> **Dataset——数据集。**

```text
Loss
```

```text
└──────────────────────────── 参数
```

```text
这个样本说：
```

```text
  ↙
    ↘
      ↓

      ↘
        ↓
```

## 九、如果看一批样本呢？

例如：

```text
batch_size = 128
```

128 个样本共同贡献一个 batch 的 Loss。

你得到的梯度更像：

```text
128 个样本综合之后：

“整体来说，往这个方向比较好。”
```

所以更新相对稳定。

但又不像整个训练集那样，每更新一次都要计算全部数据。

这形成了一个折中：

```text
单样本
│
│ 梯度噪声大
│ 更新频繁
│
▼

Mini-Batch
│
│ 效率与稳定性的折中
│ GPU 友好
│
▼

整个 Dataset
│
│ 梯度更稳定
│ 单次计算昂贵
│ 内存压力大
```

现代深度学习最常见的是：

> **Mini-Batch Gradient Descent。**

平常大家直接说 Batch，很多时候其实指的就是 mini-batch。

```text
      ↓
```

也就是说：

```text

通常更新 1 次参数
```

## 十一、Epoch 到底是什么？

教授终于写下这个天天出现的词：

### Epoch

定义很简单：

> **整个训练集被完整遍历一遍，叫一个 Epoch。**

例如：

```text
Dataset：

1000 个样本
```

设置：

```text
batch_size = 100
```

那么：

```text
1 Epoch
│
├── Batch 1 → Iteration 1
├── Batch 2 → Iteration 2
├── Batch 3 → Iteration 3
├── ...
└── Batch 10 → Iteration 10
```

所以：

```text
1 Epoch
=
10 Iterations
```

如果训练：

```text
20 Epoch
```

意味着大体上：

> 每条训练数据会被模型看到 20 次。

总 iteration：

\[
20\times10=200
\]

## 十四、Shuffle：洗牌

`shuffle=True` 可以理解为：

> **每轮重新洗牌。**

例如：

第一轮：

```text
3 8 1 7 4 2 10 5 9 6
```

分 batch：

```text
[3,8]
[1,7]
[4,2]
[10,5]
[9,6]
```

下一轮重新洗：

```text
9 2 6 1 8 5 3 10 4 7
```

于是：

```text
[9,2]
[6,1]
[8,5]
[3,10]
[4,7]
```

这样每个 Batch 的样本组合不断变化。

对于许多训练任务，这有助于减少固定数据顺序带来的问题。

所以训练集常见：

```python
train_loader = DataLoader(
    train_dataset,
    batch_size=64,
    shuffle=True
)
```

## 十六、为什么还需要 `drop_last`？

假设：

```text
数据量 = 1000
batch_size = 128
```

算一下：

\[
1000=128\times7+104
\]

所以：

```text
Batch 1 → 128
Batch 2 → 128
...
Batch 7 → 128
Batch 8 → 104
```

最后一批不完整。

默认可以正常保留。

但某些场景下，我们希望每个 batch 都严格一样大，可以：

```python
DataLoader(
    dataset,
    batch_size=128,
    shuffle=True,
    drop_last=True
)
```

那么最后：

```text
104 条
```

这一批就被丢掉。

林默点头。

“所以 `drop_last=True` 不是固定必须开的。”

“对。”

> 是否需要丢最后一个不完整 batch，要看具体模型和训练需求。

## 十七、DataLoader 还有一个真正工程化的作用

教授突然问：

“GPU 训练速度非常快，但数据在哪？”

“硬盘？”

“对。”

真实训练可能是：

```text
SSD
 ↓
读取图片
 ↓
解码
 ↓
预处理
 ↓
转 Tensor
 ↓
送入 GPU
 ↓
模型计算
```

假设 GPU 一批只需要：

```text
50ms
```

结果 CPU 读取和处理下一批需要：

```text
300ms
```

那 GPU 会变成：

```text
算完了。

……

数据呢？

……

还没来？

……
```

昂贵的 GPU 在等 CPU。

所以 DataLoader 还可以使用多个 worker：

```python

    dataset,
    batch_size=64,
    shuffle=True,
    num_workers=4
)
```

粗略理解：

```text
Worker 1 ─┐
Worker 2 ─┤
Worker 3 ─┼──► 准备 Batch ──► 训练
Worker 4 ─┘
```

多个进程/worker 提前准备数据，尽量减少模型等数据的时间。

不过 `num_workers` 并不是：

> 越大越好。

它受：

```text
CPU 核心
内存
磁盘速度
操作系统
数据预处理复杂度
```

等因素影响，需要实际测试。

## 二十、第一次完整训练

教授终于把前五章所有东西合并起来。

```python
import torch
import torch.nn as nn
from torch.utils.data import Dataset, DataLoader


# =====================
# 1. 数据
# =====================

x = torch.randn(1000, 2)
y = torch.randint(0, 3, (1000,))


class MyDataset(Dataset):

    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __len__(self):
        return len(self.x)

    def __getitem__(self, index):
        return self.x[index], self.y[index]


dataset = MyDataset(x, y)


# =====================
# 2. DataLoader
# =====================

dataloader = DataLoader(
    dataset,
    batch_size=32,
    shuffle=True
)


# =====================
# 3. 模型
# =====================

model = nn.Sequential(

    nn.Linear(2, 16),

    nn.ReLU(),

    nn.Linear(16, 3)
)


# =====================
# 4. Loss
# =====================

loss_fn = nn.CrossEntropyLoss()


# =====================
# 5. Optimizer
# =====================

optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.001
)


# =====================
# 6. Train
# =====================

for epoch in range(10):

    for batch_x, batch_y in dataloader:

        optimizer.zero_grad()

        logits = model(batch_x)

        loss = loss_fn(
            logits,
            batch_y
        )

        loss.backward()

        optimizer.step()

    print(
        "epoch:",
        epoch,
        "loss:",
        loss.item()
    )
```

林默盯着这段代码。

第一次，他没有觉得这是“一堆 PyTorch API”。

而是看到了一条完整的流水线。

```text
     ↓

```

## 二十二、Sample、Batch、Iteration、Epoch 终于不乱了

教授在黑板上写了一组数字：

```text
Dataset Size = 10,000

Batch Size = 100

Epoch = 20
```

问：

“一个 Batch 有几个 Sample？”

林默：

“100。”

“一个 Epoch 有多少 Batch？”

\[
10000/100=100
\]

“100 个。”

“一个 Epoch 大约多少 Iteration？”

“100。”

“训练 20 Epoch 呢？”

\[
20\times100=2000
\]

“2000 次 Iteration，也就是通常进行了约 2000 次参数更新。”

教授点头。

于是：

```text
Sample
↓
一条数据


Batch
↓
一批 Sample


Iteration
↓
处理一个 Batch
通常更新一次参数


Epoch
↓
完整遍历一次 Dataset
```

这四个概念，彻底分开。

## 二十四、CPU 和 GPU 是两个世界

教授写：

```python
x = torch.tensor([1, 2, 3])
```

默认通常：

```text
CPU
```

如果：

```text
x = x.cuda()
```

或者更通用地：

```text
x = x.to("cuda")
```

Tensor 就会进入：

```text
GPU
```

但这时候有一个极其经典的错误。

假设：

```text
model → GPU

x → CPU
```

然后：

```python
model(x)
```

会怎么样？

林默想了想。

“报错？”

“对。”

因为模型参数和输入数据在不同设备。

你不能让：

```text
CPU 上的数据
```

直接和：

```text
GPU 上的权重
```

做同一次普通计算。

于是实际训练代码开始变成：

```python
device = torch.device(
    "cuda" if torch.cuda.is_available()
    else "cpu"
)

model = model.to(device)

for x, y in dataloader:

    x = x.to(device)
    y = y.to(device)

    ...
```

林默看着 `device`。

他意识到 PyTorch 世界的下一扇门已经打开。
