> 阅读提示：Embedding 是可学习的查表映射，常用较低维的稠密向量，但并不要求 embedding_dim 小于词表大小，也不等于 PCA。设置 padding_idx 只处理该行的梯度等行为，不会自动替后面的均值池化或 Attention 忽略 PAD。

## 一、神经网络只认识数值

前面我们训练模型时，输入都是：

```python
x = torch.tensor([
    [1.2, 3.4],
    [2.1, 5.7]
])
```

本质都是数字。

可文本是：

```text
我喜欢 PyTorch
```

神经网络不能直接对字符做矩阵乘法：

\[
W \times \text{“我”}
\]

没有意义。

所以必须先做转换：

```text
文字
 ↓
数字
 ↓
Tensor
 ↓
神经网络
```

教授在黑板上写下第一个词：

### Token

---

## 二、Token 到底是什么

林默问：

“Token 就是一个字吗？”

“有时候是，有时候不是。”

Token 可以是：

```text
一个字
一个词
一个词的一部分
标点
特殊符号
```

比如一句英文：

```text
I love PyTorch
```

一种最简单的切法：

```text
["I", "love", "PyTorch"]
```

三个 Token。

中文：

```text
我喜欢PyTorch
```

可能切成：

```text
["我", "喜欢", "PyTorch"]
```

也可能：

```text
["我", "喜", "欢", "Py", "Torch"]
```

不同 tokenizer 规则不同。

---

## 三、为什么不能直接“一个词一个 Token”

林默说：

“那按照词切不就行了吗？”

教授写：

```text
北京
上海
程序员
神经网络
大模型
反向传播
```

看起来没问题。

但语言中的词太多了。

比如：

```text
ChatGPT
ChatGPT-6
PyTorch
PyTorch2
foobar123
某个新出现的名字
```

如果每个完整词都必须提前放进词表，那么：

> 新词怎么办？

词表会无限膨胀。

所以现代大模型常用的是：

> **Subword Tokenization——子词切分。**

也就是：

```text
unbelievable
```

可能拆成：

```text
un
believ
able
```

这样模型不需要记住世界上所有完整单词。

## 四、Tokenizer 的两个核心工作

教授写：

```text
文本
 ↓
Tokenizer
 ↓
Token
 ↓
Token ID
```

Tokenizer 主要干两件事。

第一：

> 把文本切成 Token。

第二：

> 给每个 Token 一个整数编号。

例如词表：

```text
0  <pad>
1  <unk>
2  我
3  喜欢
4  PyTorch
5  Java
```

那么：

```text
我 喜欢 PyTorch
```

就变成：

```text
[2, 3, 4]
```

于是 PyTorch 终于能处理：

```python
token_ids = torch.tensor([2, 3, 4])
```

林默点头。

“所以 Token ID 就是 Token 的编号。”

“对。”

但教授马上补充：

> **Token ID 本身没有语义。**

---

## 五、为什么 Token ID 不能直接输入神经网络

假设：

```text
猫 = 10
狗 = 11
飞机 = 100
```

如果直接把 ID 当数值：

```text
猫 = 10
狗 = 11
飞机 = 100
```

模型可能误以为：

```text
狗比猫大 1
飞机比猫大 90
```

但这个数字差没有语义。

Token ID 只是数据库主键一样的东西。

就像：

```text
user_id = 10001
user_id = 10002
```

不能说明第二个人比第一个人大一点。

所以需要下一步。

## 六、Embedding 登场

教授写：

```python
embedding = nn.Embedding(
    num_embeddings=10000,
    embedding_dim=128
)
```

林默看着这个 API。

“这是什么？”

教授说：

“它可以理解成一张巨大的向量表。”

假设词表只有 5 个 Token，每个 Token 用 3 维向量表示：

```text
Token 0 → [ 0.2, -0.1,  0.7]
Token 1 → [-0.4,  0.9,  0.3]
Token 2 → [ 0.8,  0.1, -0.2]
Token 3 → [ 0.5, -0.7,  0.6]
Token 4 → [-0.2,  0.4,  0.9]
```

这张表就是：

\[
Embedding\ Matrix
\]

形状：

```text
[vocab_size, embedding_dim]
```

---

## 七、`nn.Embedding` 本质上就是查表

假设：

```python
embedding = nn.Embedding(10000, 128)
```

内部参数形状：

```text
[10000, 128]
```

也就是说：

```text
10000 个 Token
每个 Token 128 维
```

输入：

```python
token_ids = torch.tensor([2, 5, 9])
```

执行：

```text
x = embedding(token_ids)
```

得到：

```text
shape = [3, 128]
```

本质上就是：

```text
取第2行
取第5行
取第9行
```

所以 `Embedding` 可以粗略理解成：

> **用 Token ID 去查对应向量。**

## 八、那这些向量是谁定的？

林默问：

“难道人工规定？”

教授摇头。

“最重要的地方来了。”

这些 Embedding：

> **也是模型参数。**

也就是：

```text
embedding.weight
```

本身就是：

```text
Parameter
```

训练开始时可能随机：

```text
猫 → [0.12, -0.54, 0.33, ...]
狗 → [-0.72, 0.19, 0.05, ...]
```

然后通过：

```text
Loss
 ↓
backward
 ↓
optimizer.step()
```

不断调整。

所以：

> **词向量不是人写进去的，而是训练出来的。**

## 九、语义为什么会出现在向量里

教授写两句话：

```text
我养了一只猫。

我养了一只狗。
```

在大量语料中：

```text
猫
狗
```

经常出现在相似上下文。

比如：

```text
喂__
抱__
宠物__
可爱的__
```

那么为了完成语言预测任务，模型会逐渐学到：

> 猫和狗在很多语境中有相似功能。

于是它们的向量可能越来越接近。

比如：

```text
猫 → [0.7, 0.3, -0.2, ...]
狗 → [0.68, 0.29, -0.18, ...]
```

而：

```text
数据库
```

可能离得很远。

这就是：

> **语义进入向量空间。**

## 十、向量距离开始有意义了

假设二维世界：

```text
          猫 ●
              狗 ●

                         飞机 ●
```

猫和狗距离近：

```text
相似
```

数据库较远：

```text

```

于是可以用：

```text

```

等指标衡量语义相似程度。

## 十一、RAG 的 Embedding 和 LLM 的 Token Embedding 是一回事吗？

这是一个非常容易混淆的问题。

教授写：

```text
LLM 内部 Token Embedding
```

和：

```text
RAG 文本 Embedding
```

它们都叫 Embedding。

但用途不同。

---

### LLM 的 Token Embedding

输入：

```text
Token ID
```

输出：

```text
一个 Token 的向量
```

比如：

```text
[batch, seq_len]
```

经过：

```python
nn.Embedding(...)
```

得到：

```text
[batch, seq_len, hidden_dim]
```

它是：

> Transformer 内部表示的起点。

---

### RAG Embedding

输入通常是：

```text
一句话
一个段落
一个 chunk
```

输出：

```text
一个整体语义向量
```

例如：

```text
“Redis 为什么快？”
 ↓
[0.123, -0.312, ..., 0.88]
```

然后存进：

```text
pgvector
Milvus
FAISS
```

做相似度检索。

所以：

```text
Token Embedding
→ token 级


RAG Embedding
→ 文本片段级
```

虽然背后可能都用神经网络产生向量，但不能简单当成同一个东西。

## 十二、Embedding 为什么不是 One-Hot

教授又画出旧时代的方法。

假设词表：

```text
猫
狗
鸟
车
```

One-Hot：

```text

狗 = [0,1,0,0]
鸟 = [0,0,1,0]
车 = [0,0,0,1]
```

问题来了。

猫和狗：

距离？

猫和车：

距离？

从这种表示本身看：

> 都一样远。

One-Hot 不携带语义相似性。

而 Embedding：

```text
猫 = [0.81, 0.23, -0.11]
狗 = [0.79, 0.25, -0.09]
车 = [-0.42, 0.61, 0.77]
```

猫狗就可以自然靠近。

## 十三、Embedding 其实是降维

假设词表：

```text

```

所以：

```text

 ↓
```

这也是深度学习非常关键的思想。

## 二十五、PyTorch 中的一个微型 NLP 模型

教授说：

“先不学 Transformer，我们做一个极简文本分类。”

词表：

```text
0 PAD
1 我
2 喜欢
3 PyTorch
4 Java
5 讨厌
```

模型：

```python
import torch
import torch.nn as nn


class TextClassifier(nn.Module):

    def __init__(self, vocab_size, embed_dim, num_classes, pad_id=0):
        super().__init__()

        self.pad_id = pad_id
        self.embedding = nn.Embedding(
            vocab_size, embed_dim, padding_idx=pad_id
        )

        self.fc = nn.Linear(
            embed_dim,
            num_classes
        )

    def forward(self, token_ids):

        x = self.embedding(token_ids)

        mask = (token_ids != self.pad_id).unsqueeze(-1)
        x = (x * mask).sum(dim=1) / mask.sum(dim=1).clamp_min(1)

        logits = self.fc(x)

        return logits
```

林默盯住：

```python
mask = (token_ids != self.pad_id).unsqueeze(-1)
x = (x * mask).sum(dim=1) / mask.sum(dim=1).clamp_min(1)
```

“这是干什么？”

教授说：

“先把所有 Token 向量取平均。”

例如：

```text

```

变成：

```text

```

相当于把一句话压成一个向量。
