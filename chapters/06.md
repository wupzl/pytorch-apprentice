## 十二、GPU 显存里面到底放什么？

林默问：

“显存为什么这么容易爆？”

教授画：

GPU 显存：

```text
┌──────────────────┐
│ 模型参数          │
│                  │
│ weight           │
│ bias             │

├──────────────────┤

│                  │
│ grad             │
│                  │
├──────────────────┤
│ optimizer状态     │
│                  │
├──────────────────┤
│ 输入数据          │
│                  │
├──────────────────┤
│ 中间激活          │
│                  │
└──────────────────┘
```

### 1. 模型参数

例如：

GPT 有：


每个参数：

4 byte

那么：

\[

仅参数。

### 2. Gradient

训练需要：

```python

```

所以每个参数需要保存：

```text
weight
+
gradient
```

额外占空间。

---

### 3. Optimizer 状态

例如 Adam：

除了：

```text

```

还保存：

```text
一阶动量

二阶动量
```

所以：

显存压力很大。

### 4. Activation

这是很多人忽略的。

前向：

```text

 ↓
Linear
 ↓
ReLU
 ↓
Linear
 ↓
Loss
```

反向传播需要知道：

```text

```

所以很多 activation 要保存。

Batch 越大：

```text
输入更多
 ↓
中间结果更多
 ↓
显存增加
```

这也是为什么：

```text

```

经常卡显存。

## 十三、`torch.no_grad()` 到底省什么？

上一章我们见过：

```python
with torch.no_grad():

    pred = model(x)
```

很多人理解：

“关闭梯度。”

不够准确。

教授写：

训练：

```text
forward

↓

保存计算图

↓

backward需要
```

例如：

```text
x
 ↓
Linear
 ↓
ReLU
 ↓
Loss
```

PyTorch 需要记录：

```text
谁依赖谁
```

---

但是推理：

```text
输入
 ↓
模型
 ↓
输出
```

你不会：

```python
loss.backward()
```

所以：

这些东西没有意义：

```text
计算图
梯度记录
activation缓存
```

于是：

```python
with torch.no_grad():
    ...  # 此处只展示结构，完整代码见上下文
```

告诉 PyTorch：

> 不需要记录梯度相关信息。

结果：

```text
更少显存

更快推理
```

## 十四、但是 `no_grad()` ≠ `eval()`

这是今天最容易混淆的地方。

林默写：

```text
model.eval()
```

教授问：

“什么意思？”

林默：

“关闭梯度？”

“不对。”

---

### `eval()` 是切换模型行为

有些层：

训练和推理行为不同。

最典型：

```text
Dropout

BatchNorm
```

---

## 十五、Dropout

教授画：

训练：

```text
神经元：

○ ○ ○ ○ ○
```

Dropout：

随机关闭：

```text
○ × ○ × ○
```

目的：

防止模型过度依赖某些神经元。

训练时：

```text
model.train()
```

Dropout 开启。

---

推理：

你希望：

```text
所有神经元正常工作
```

所以：

```text
model.eval()
```

关闭 Dropout。

---

## 十六、BatchNorm

BatchNorm 更复杂。

简单理解：

训练时：

它根据当前 batch：

计算：

```text
均值
方差
```

然后归一化。

但是推理时：

没有不断变化的 batch。

所以：

```text
训练：
使用当前batch统计


推理：
使用训练期间保存的统计量
```

所以：

```text
model.eval()
```

会改变 BatchNorm 行为。

---

## 十七、训练和推理正确写法

训练：

```python
model.train()


for x,y in dataloader:

    pred = model(x)

    loss = loss_fn(
        pred,
        y
    )

    loss.backward()

    optimizer.step()
```

---

推理：

```python
model.eval()


with torch.no_grad():

    pred = model(x)
```

注意：

两个东西分别负责：

```text
model.train()
model.eval()

↓

改变模型运行模式


torch.no_grad()

↓

是否记录梯度
```

## 十八、一个经典错误

错误：

```python
model.eval()

pred = model(x)

loss = loss_fn(pred,y)

loss.backward()
```

为什么错？

因为：

```text
eval()
```

只是：

```text
Dropout关闭
BatchNorm切换
```

它没有禁止：

```text
梯度计算
```

如果你不需要训练：

应该：

```python
with torch.no_grad():
    ...  # 此处只展示结构，完整代码见上下文
```

---

另一个错误：

```python
with torch.no_grad():

    model.train()
```

这也是奇怪组合。

因为：

你告诉 PyTorch：

```text
我要训练模式
```

但是：

```text
不要记录梯度
```

通常没有意义。

## 十九、完整训练/验证结构

真实项目通常：

```python
for epoch in range(10):

    # ===== Train =====

    model.train()

    for x,y in train_loader:

        x = x.to(device)
        y = y.to(device)

        optimizer.zero_grad()

    model.eval()

    with torch.no_grad():

        for x,y in val_loader:

            x = x.to(device)
            y = y.to(device)

            pred = model(x)

            loss = loss_fn(
                pred,
                y
            )
```
